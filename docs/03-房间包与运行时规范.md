# 千万间 Roomillion 房间包与运行时规范

## 1. 状态与适用范围

- 规范版本：`0.1-draft`
- 包扩展名：`.room`
- 目标：定义可移植、可验证、可升级的房间程序格式
- 不包含：工作台安装包格式、用户数据快照格式、公共市场协议

本文中的“必须”“不得”表示实现和房间都需要遵守；“建议”表示默认做法，可通过后续 ADR 调整。

## 2. 基本模型

一个房间由以下部分组成：

1. 只读的程序资源。
2. 声明式清单。
3. 对工作台能力的权限请求。
4. 数据库迁移。
5. 完整性信息和可选签名。

房间包不得默认携带用户运行数据。房间运行时不得假设设备已安装 Node、Bun、Git、数据库服务或 npm 包。

## 3. 容器格式

`.room` 是使用确定性规则生成的 ZIP 容器。所有路径必须使用 UTF-8 和 `/` 分隔符。

```text
example.room
├─ manifest.json
├─ assets/
│  └─ icon.svg             # 可选房间图标，也可使用 PNG/JPEG/WebP
├─ app/
│  ├─ index.html
│  ├─ assets/
│  └─ app.js
├─ migrations/
│  ├─ 0001.sql
│  └─ 0002.sql
├─ embedded/              # 可选，经过允许的只读依赖
├─ integrity.json
└─ signature.json         # 可选签名
```

### 3.1 路径规则

- 不得包含绝对路径、盘符、反斜杠或 `..` 路径段。
- 文件名比较按规范化后的 Unicode 处理，打包器必须检测大小写冲突。
- 不得包含符号链接、硬链接、设备文件和命名管道。
- 必须限制总解压大小、单文件大小、文件数量和压缩比。
- `manifest.json`、`integrity.json` 必须位于根目录且只能出现一次。

## 4. Manifest

### 4.1 示例

```json
{
  "formatVersion": "0.1",
  "id": "cn.example.inventory",
  "name": "物资台账",
  "version": "1.2.0",
  "publisher": {
    "id": "cn.example",
    "name": "示例组织"
  },
  "runtime": {
    "roomSdk": "1",
    "minimumWorkbench": "0.1.0"
  },
  "entry": "app/index.html",
  "icon": "assets/icon.svg",
  "permissions": {
    "database": "private",
    "files": ["pick", "pickMany", "directoryRead", "directoryWrite", "export", "largeText"],
    "ai": { "roles": ["general", "vision"] },
    "compute": ["worker"],
    "tools": ["document.markdown-to-pdf@1"],
    "credentials": ["book-api"],
    "browser": ["navigate", "download"],
    "network": ["https://api.example.com", "http://intranet:8080"]
  },
  "hostModules": [
    "data.date@1",
    "data.decimal@1",
    "data.csv@1"
  ],
  "embeddedDependencies": [],
  "database": {
    "schemaVersion": 2,
    "migrations": [
      "migrations/0001.sql",
      "migrations/0002.sql"
    ]
  }
}
```

### 4.2 必填字段

| 字段 | 规则 |
|---|---|
| `formatVersion` | 房间容器格式版本 |
| `id` | 稳定、全局唯一，更新时不得改变 |
| `name` | 用户可见名称 |
| `version` | 语义化版本 |
| `runtime.roomSdk` | 依赖的 Room SDK 主版本 |
| `runtime.minimumWorkbench` | 最低工作台版本 |
| `entry` | 包内 HTML 入口，必须位于 `app/` |
| `permissions` | 完整权限声明；未声明即无权限 |
| `hostModules` | 使用的工作台官方模块和主版本 |
| `embeddedDependencies` | 工作台目录外、必须随房间分发的固定版本纯 Web 依赖 |

`icon` 是可选展示字段，必须指向 `assets/` 下的 SVG、PNG、JPEG 或 WebP。图标不再设置人为的产品体积上限，但仍受房间包的技术性解压边界约束。SVG 只允许静态图形和文字，脚本、事件处理器、外部资源及活动内容会被拒绝。没有 `icon` 的旧房间继续用名称首字显示。AI 新建房间默认生成图标；创建者明确指定最近上传的 PNG/JPEG/WebP 时，可将该图片复制进房间包。图标属于程序资源，会参与完整性校验并随 `.room` 导出。

工作台不得信任清单中的展示文本。导入界面必须转义内容，并对 ID、版本、路径和字段长度进行校验。

### 4.3 Agent 生成的两种房间源格式

`manifest.json` 和 `.room` 容器保持统一；Agent 在编译前可以使用两种源格式：

- `room-spec@1`：声明式页面、数据源、组件和动作。适合办公、台账、看板、计算器，编译器负责生成应用代码。
- `room-app@1`：沙箱内自由 HTML body 入口、基础 CSS、JavaScript 入口，以及任意数量、任意安全相对路径的本地文本模块。入口脚本可用静态 `import/export` 组合 `modules/`、`views/`、`services/` 等目录；额外 CSS 会自动随页面加载。适合新游戏、新交互和固定组件无法表达的应用。

`room-app@1` 不是放开系统代码执行。它必须经过 Agent Harness 的草拟、静态检查、契约测试和最终复检，且满足：

- HTML 不含脚本、内联事件、文档外壳、嵌入页面或外部 URL；
- CSS 不含远程资源、`@import` 或动态表达式；
- JavaScript 不含 Node/Electron、直接网络 API、动态代码执行、导航或 HTML 字符串注入；只有声明 `permissions.compute: ["worker"]` 后才可创建包内同源 Web Worker，Service Worker 与 SharedWorker 仍禁止；
- 只能使用 Manifest 声明的工作台官方模块和按权限注入的 `window.room` SDK；
- `permissions.network` 只能填写精确 HTTP/HTTPS 源（协议、主机、端口），代码只能通过 `window.room.network` 受控访问；官方模块只引用宿主公共层，不复制到房间包；
- 只有明确的网页浏览需求才可声明 `permissions.browser: ["navigate"]`；需要下载时再增加 `"download"`。房间只能通过 `window.room.browser` 控制宿主网页视图，不得使用 `iframe`、`webview`、`window.open` 或自行实现通用网络代理；
- 最终仍由相同 CSP、WebContents 沙箱、权限门和可移植性审计约束。

## 5. 依赖规则

### 5.1 官方宿主模块

房间优先使用工作台提供的版本化模块，例如：

- `data.date@1`
- `data.decimal@1`
- `data.csv@1`
- `data.search@1`
- `ui.chart@1`
- `security.sanitize@1`
- `document.markdown@1`

模块名称是能力契约，不等同于 npm 包名。工作台可以替换内部实现，但不得破坏同一主版本的公开接口。

当前实现接受经过审核的官方模块目录（目前 39 个能力 ID）；未知 ID、重复声明和缺少强制依赖都会在导入前拒绝。`document.markdown@1`、`diagram.mermaid@1` 和 `editor.richtext@1` 必须同时声明 `security.sanitize@1`，`game.assets@1` 必须同时声明 `graphics.three@1`。模块资源由工作台统一离线提供，房间不能通过模块路径越权读取未声明能力。固定版本、许可证与资源哈希见《18-官方房间模块目录与AI自动选型》以及发行物中的合规清单。

### 5.2 内嵌依赖

只有房间编译器允许的纯 Web 依赖才可进入 `embedded/`，并必须：

- 固定精确版本和内容哈希。
- 记录许可证和来源。
- 不包含原生二进制、安装脚本和动态下载器。
- 被打入最终静态资源，不在运行时执行模块解析或安装。
- 通过漏洞和策略扫描。

当前实现要求内嵌依赖统一位于 `embedded/<依赖-id>/`，并在 `embeddedDependencies` 中登记包名、精确版本、许可证、来源、根目录、许可证文件、全部文件和入口资源。`embedded/` 中不得存在未声明文件，也不得携带整个 `node_modules`。完整规则、v1 冻结策略和旧房间兼容见《19-v1房间依赖打包策略》。

### 5.3 禁止项

- 运行时 `npm install`、`bun install` 或从 CDN 加载脚本。
- Node/Bun 内置模块，例如 `fs`、`child_process`、`net`。
- 平台专属 `.dll`、`.so`、`.exe` 和原生 Node 插件。
- 动态拼接的外部模块地址。
- 未在清单中声明的网络连接，或绕过 `room.network` / `room.browser` 的网页加载。

## 6. 权限模型

权限采用“默认拒绝 + 能力授权”。权限授予房间 ID 和发布者，而不是授予某个文件路径中的任意代码。

### 6.1 权限等级

| 等级 | 示例 | 交互 |
|---|---|---|
| 基础私有能力 | 房间私有 SQLite、少量设置 | 首次导入说明，可默认允许 |
| 用户手势能力 | 选择文件、导出文件、剪贴板读取 | 每次操作或持久句柄授权 |
| 敏感能力 | AI、摄像头、麦克风、共享数据源 | 首次使用明确授权，可撤销 |
| 高风险能力 | 受控访问精确网络源、浏览任意网站、网页下载、外部程序、广泛目录访问 | 网络源逐项授权；浏览器需单独授权并受全局联网开关控制；外部程序和广泛目录仍不开放 |

### 6.2 权限变化

- 更新版本新增权限时必须重新提示。
- 删除权限应立即收回相应句柄和令牌。
- 发布者或房间 ID 变化按新房间处理。
- 权限记录不得随 `.room` 分享给其他用户。

## 7. Room SDK

Room SDK 必须通过窄接口暴露能力，不暴露 Electron、Node 或通用 IPC。

```ts
interface RoomApi {
  app: RoomAppApi;
  storage: RoomStorageApi;
  db: RoomDatabaseApi;
  vector: RoomVectorApi;
  files: RoomFilesApi;
  largeText: RoomLargeTextApi;
  blobs: RoomBlobApi;
  artifacts: RoomArtifactApi;
  documents: RoomDocumentApi;
  tools: RoomToolsApi;
  credentials: RoomCredentialsApi;
  ai: RoomAiApi;
  network: RoomNetworkApi;
  browser: RoomBrowserApi;
  jobs: RoomJobsApi;
  // A Room may also create same-origin Web Workers when compute.worker is granted.
  ui: RoomUiApi;
}
```

### 7.1 数据库

- 每个房间使用独立数据库文件或严格独立的逻辑数据库。
- 所有查询使用参数绑定。
- 默认禁止 `ATTACH` 任意数据库和加载 SQLite 扩展。
- 迁移由工作台在房间代码启动前执行。
- 迁移必须按序、不可重复，并记录已应用版本。

### 7.2 文件

向量集合 `RoomVectorApi`、`room.ai.embed()`、大文件 `room.files.openBinary/readBinary/closeBinary()` 及最新容量上限详见 [38-向量数据库与大文件房间接口](./38-向量数据库与大文件房间接口.md)。向量数据沿用 `database.private` 权限和房间数据导出规则；大文件读取沿用 `files.pick` 授权。

- `pick` 返回授权句柄或受控内容，不把任意绝对路径作为通用能力。
- 私有文件 API 的路径根固定在房间数据目录。
- 导出必须由用户选择目标或使用明确的下载位置策略。
- 授权句柄应可撤销，并在文件失效时返回明确错误。

超长文本使用独立的 `files.largeText` 权限。它不是任意文件系统权限：用户每次在系统窗口中选择一个文件，房间只获得临时令牌、文件名、大小、编码和分块结果，不获得绝对路径。当前 SDK 接口为：

```ts
interface RoomLargeTextApi {
  open(options?: { encoding?: "auto" | "utf8" | "gb18030" | "utf16le" | "utf16be" | "big5" }): Promise<LargeTextFile | null>;
  readNext(token: string, options?: { maxBytes?: number }): Promise<LargeTextChunk>;
  reset(token: string): Promise<LargeTextPosition>;
  setEncoding(token: string, encoding: string): Promise<LargeTextFile>;
  startSearch(token: string, query: string, options?: { caseSensitive?: boolean; maxResults?: number }): Promise<{ taskId: string }>;
  cancelTask(taskId: string): Promise<boolean>;
  close(token: string): Promise<boolean>;
  onTaskEvent(callback: (event: LargeTextTaskEvent) => void): () => void;
}
```

一次分块最多读取 1 MB 原始字节；后台搜索不改变预览游标，并通过进度、完成、取消或错误事件返回状态。源文件被替换、大小或修改时间变化时，后续操作必须失败并要求重新选择。完整实现边界见《21-超长文本流式处理设计与使用指南》。

### 7.3 AI

- 主工作台维护多套模型配置和一个默认模型；每个房间可以保存自己的模型选择，切换房间模型不会改变工作台默认模型。
- 房间只取得脱敏模型目录。目录可包含配置 ID、显示名称、Provider 名称、模型名、输入能力、上下文窗口、就绪状态和默认/选中状态；不得包含 API Key、认证头或自定义服务地址。
- AI Gateway 校验房间权限、模型能力、用量和超时。
- 房间无法读取凭据、认证头和其他房间上下文。
- 发送用户文件内容前必须满足权限和用户可理解的用途说明。

当前 `RoomAiApi`：

```ts
interface RoomAiModel {
  embeddingTransport: "openai-compatible" | null;
  id: string;
  label: string;
  providerId: string;
  providerName: string;
  model: string;
  input: string[];
  supportsImages: boolean;
  contextWindow: number | null;
  maxTokens: number | null;
  hasCredential: boolean;
  ready: boolean;
  isDefault: boolean;
  isSelected: boolean;
}

interface RoomAiApi {
  embed(texts: string[], options: { profileId?: string; model: string; dimensions?: number }): Promise<{
    embeddings: number[][]; dimensions: number; embedding: string; model: string; profileId: string;
    usage: { input: number | null; totalTokens: number | null };
  }>;
  listModels(): Promise<RoomAiModel[]>;
  getSelection(): Promise<{ profileId: string | null; source: "room" | "default" }>;
  selectModel(profileId: string): Promise<{ profileId: string; source: "room" }>;
  generate(prompt: string, options?: {
    requestId?: string;
    onChunk?: (delta: string, full: string) => void;
    profileId?: string;
    images?: Array<{ mimeType: "image/png" | "image/jpeg" | "image/webp" | "image/gif"; data: Uint8Array | ArrayBuffer }>;
    maxTokens?: number;
    temperature?: number;
    structuredOutput?: boolean;
    timeoutMs?: number;
  }): Promise<{
    text: string;
    model: string;
    profileId: string;
    usage?: unknown;
  }>;
  cancel(requestId: string): Promise<{ cancelled: boolean }>;
  onModelsChanged(callback: () => void): () => void;
}
```

图片调用必须同时满足房间已获 `ai.vision` 权限、所选模型目录声明 `supportsImages: true`，并经过 Gateway 的图片格式和魔数校验。图片数量和体积不再设置人为产品上限，实际可用规模由模型上下文、提供商请求上限、IPC/内存和设备能力决定；大批图片应分轮发送。房间只能传递 PNG、JPEG、WebP 或 GIF 的二进制内容。`maxTokens` 只需是正整数；工作台会遵循所选模型目录声明的真实输出上限，模型未声明上限时交由提供商处理。`timeoutMs` 可按任务设置；`temperature` 只要求为有限数字，最终可用范围由提供商决定。`structuredOutput: true` 会在 Provider 兼容时请求 JSON 对象。图片与凭据均不写入工作台诊断日志。

所有方法都要求房间已获 AI 权限。`generate(prompt)` 向后兼容：未指定 `profileId` 时使用房间选择；房间没有独立选择时自动跟随主工作台默认模型。模型配置被删除后，使用它的房间也会自动回退到当前默认模型。

流式显示使用 `onChunk(delta, full)`。要允许取消，在 `generate` 的选项中传入每次唯一的 `requestId`，再调用 `cancel(requestId)` 中止同一页面的该次请求；标识为 1–101 个英文字母、数字、点、下划线、冒号或连字符，首字符须为字母或数字。取消会传递到模型连接，原 Promise 拒绝；已结束或不属于当前页面的请求返回 `{cancelled:false}`。房间关闭或重载会中止其未完成请求。房间应忽略已取消请求的排队回调，不把半成品保存为成功历史；新翻译须用新的标识。不要跨 IPC 传递 AbortSignal。

只有一个 AI 角色的房间可调用 `selectModel(profileId)` 保存房间默认选择。辩论、评审、协作等多角色房间应为每个角色保存独立的配置 ID，并在每次调用时传入 `generate(prompt, { profileId })`；这种单次路由不会修改房间默认选择，也不会让不同角色互相覆盖。房间应在启动和收到 `onModelsChanged` 事件时重新读取目录；已删除或未就绪的配置必须要求用户重新选择或回退到可用默认模型。

### 7.4 受控网络

房间联网与 AI Gateway 是两项独立能力。工作台只要能连接用户配置的模型端点，`room.ai` 和 AI 创建房间就可以工作，不受“允许房间联网”总开关影响。普通业务联网必须同时满足：

1. Manifest 的 `permissions.network` 精确声明目标源；
2. 用户授予当前房间对应源的权限；
3. 主工作台“联网控制”中的“允许已授权房间联网”总开关已启用。

源只包含协议、主机和可选端口，例如 `https://api.example.com`、`http://intranet:8080`，不得包含路径、查询、片段、用户名或密码。跳转后的每一个目标也必须属于已授权源。

```ts
interface RoomNetworkStatus {
  workbenchAllowed: boolean;
  roomAllowed: boolean;
  available: boolean;
  allowedOrigins: string[];
}

interface RoomNetworkResponse {
  ok: boolean;
  status: number;
  statusText: string;
  url: string;
  headers: Record<string, string>;
  text: string;
  bytes: number;
}

interface RoomNetworkApi {
  getStatus(): Promise<RoomNetworkStatus>;
  request(options: {
    url: string;
    method?: "GET" | "HEAD" | "POST" | "PUT" | "PATCH" | "DELETE";
    headers?: Record<string, string>;
    body?: string | Record<string, unknown> | unknown[];
    timeoutMs?: number;
    maxRedirects?: number;
    credentialAlias?: string;
  }): Promise<RoomNetworkResponse>;
  open(options: NetworkRequestOptions): Promise<Omit<RoomNetworkResponse, "text" | "bytes"> & { token: string }>;
  read(token: string, options?: { maxBytes?: number }): Promise<{ data: Uint8Array; bytes: number; done: boolean }>;
  close(token: string): Promise<boolean>;
  onStatusChanged(callback: (status: RoomNetworkStatus) => void): () => void;
}
```

小响应可继续调用 `request()`；大响应、SSE 或二进制响应应使用 `open()` → 多次 `read()` → `close()`，避免把完整响应堆进一次 IPC。请求体和响应体不再设置人为产品上限，超时及最大跳转次数可由任务设置，每一次跳转仍重新校验授权源。实现继续过滤 Cookie、Host、Origin、代理认证等危险头。房间不得使用 `fetch`、XHR、WebSocket、EventSource、Beacon 或通过网络下载脚本、模块、字体和可执行内容。外部导入房间的网络权限默认不授予；用户可在导入权限确认中逐项决定。

### 7.5 受控浏览器

通用网页浏览不是 `permissions.network` 的扩大版本。浏览器房间声明 `permissions.browser`，网页由宿主创建独立的持久化 `WebContentsView`，房间只负责地址栏、标签栏和交互控制。网页视图关闭 Node 集成、开启上下文隔离与沙箱，不注入 Room SDK，因此网页无法读取房间数据库、主工作台 AI 凭据或其他房间数据。

```ts
interface RoomBrowserTab {
  id: string;
  title: string;
  url: string;
  loading: boolean;
  canGoBack: boolean;
  canGoForward: boolean;
  crashed: boolean;
  error: string | null;
}

interface RoomBrowserState {
  roomId: string;
  activeTabId: string | null;
  tabs: RoomBrowserTab[];
  networkAllowed: boolean;
  permissions: { navigate: boolean; download: boolean };
  maximumTabs: number;
}

interface RoomBrowserApi {
  getState(): Promise<RoomBrowserState>;
  createTab(input?: string): Promise<RoomBrowserState>;
  closeTab(tabId: string): Promise<RoomBrowserState>;
  activateTab(tabId: string): Promise<RoomBrowserState>;
  navigate(tabId: string, input: string): Promise<RoomBrowserState>;
  goBack(tabId: string): Promise<RoomBrowserState>;
  goForward(tabId: string): Promise<RoomBrowserState>;
  reload(tabId: string): Promise<RoomBrowserState>;
  stop(tabId: string): Promise<RoomBrowserState>;
  setViewport(bounds: { x: number; y: number; width: number; height: number }): Promise<RoomBrowserState>;
  clearData(options?: { cookies?: boolean; storage?: boolean; cache?: boolean }): Promise<{ cleared: boolean; hadSession: boolean }>;
  respondToPermission(requestId: string, allowed: boolean): Promise<boolean>;
  onStateChanged(callback: (state: RoomBrowserState) => void): () => void;
  onDownload(callback: (event: unknown) => void): () => void;
  onPermissionRequest(callback: (request: { requestId: string; origin: string; permission: string; label: string }) => void): () => void;
}
```

规则如下：

- `browser.navigate` 允许访问任意 HTTP/HTTPS 网站，风险高于精确源业务请求，外部房间默认不授权；所有请求仍必须经过主工作台“允许房间联网”总开关。
- `browser.download` 依赖 `browser.navigate`；每个文件必须经过系统保存窗口由用户选择目标。关闭联网或撤销权限会取消进行中的下载、网站授权并销毁当前网页渲染视图，以终止既有长连接；标签地址和标题保留，重新联网后可由用户刷新重建。
- 默认最多同时创建 12 个网页标签；`window.open` 只能转换为受控标签，其他协议和带用户名/密码的网址一律拒绝。
- 摄像头、麦克风、位置、通知、剪贴板、MIDI、鼠标锁定和空闲检测等网站权限默认拒绝；受支持的请求必须由浏览器房间显示来源，并取得用户本次明确同意。
- 每个房间 ID 使用独立浏览会话。收藏夹和历史等房间业务数据可随“应用和数据”导出；Cookie、登录态、站点存储、缓存和网站授权不进入 `.room`，即使导出时包含数据并设置密码也不会携带。
- 卸载时“保留数据”保留浏览会话以便重装恢复；“同时删除数据”清除房间数据库、Cookie、站点存储、缓存和临时网站授权。
- 房间拖入独立窗口或收回主工作台时，宿主只重挂同一个网页视图，不重新加载页面；隐藏标签时网页视图必须从可见窗口移除。

完整边界和示例见《37-room-browser-v1规范与浏览器房间》。

### 7.6 Blob、制品、文档与可恢复任务

`room.blobs` 在房间私有数据目录中分块保存中间内容，`room.artifacts` 保存最终 Markdown、PDF 或其他制品。`begin/write/finish/abort` 单块最多 64 MiB，适合避免把整本书或全部图片放进一次 IPC。`room.documents.markdownToPdf()` 使用工作台内置 CJK 字体输出分页 PDF 制品。

“应用和数据一起导出”的 `.room` 传输格式 0.3 除 SQLite 快照外，还包含 Blob 索引与其引用的二进制文件、任务检查点和私有 `files` 目录。导入时逐文件校验大小与 SHA-256，并将这些数据作为一个房间数据集替换；旧版 0.2 传输包仍按原语义仅恢复 SQLite。`.zdata` 0.1 只备份 SQLite，不适合单独迁移依赖 Blob/制品的房间；数据库检查点也不包含 Blob/制品。模型配置、API Key、目录授权和浏览器会话不随包迁移，目标设备需要重新配置或授权。

`room.jobs` 保存通用任务类型、状态、进度、检查点、结果和错误。状态为 `queued/running/paused/completed/failed/cancelled`；房间启动后调用 `recover()`，工作台会把上次异常中断的 running 任务恢复到队列。任务只接受结构化数据，不能提交 Shell、可执行路径或 JavaScript 源码。

### 7.7 宿主工具、命名凭据与声明式测试

`room.tools.list/call` 只显示并调用 Manifest 中声明、用户已授权且当前工作台已注册的版本化工具 ID。工具输入限制为结构化数据；大内容应传 Blob 或制品 ID。当前内置 `document.markdown-to-pdf@1` 和 `artifact.list@1`，插件可向同一注册表增加处理器。

命名凭据由工作台设置页管理并绑定精确服务源。房间通过 `room.credentials.list()` 只能看到别名、服务源和可用状态，在 `room.network.request/open` 中用 `credentialAlias` 请求宿主注入。明文不返回房间；重定向到其他源时凭据绑定校验会失败。

批量文件或视觉 AI 房间应携带 `app/room-tests.json`，用 `click/input/wait/reload/assertExists/assertText` 描述关键业务场景，并可在 `mocks.ai` 中提供隔离测试响应。Harness 在安装前执行启动、重载、通用按钮探测和声明式场景；不调用真实 AI 或真实外部网络。

持久化场景可在保存后执行 `{ "type": "reload" }`，重载同一房间（保留私有数据库、清除页面内存），再用 `wait/assertText` 等待异步加载并断言数据。`mocks.ai` 项可加 `chunkDelayMs`（0–1000 毫秒），让每 3 字符分段延时，用于测试流式取消及重复点击。使用 `{ "error": "模拟服务暂时不可用" }` 可让一次调用失败，再用下一条正常响应验证重试恢复。`click` 动作支持 `count: 1–30`，对同一控件同步连续点击，覆盖首次点击重绘或移除按钮时的重入保护。

## 8. 生命周期

### 8.1 导入

1. 在随机临时目录安全解包。
2. 校验格式、路径、大小、哈希和签名。
3. 解析兼容性与权限。
4. 向用户展示导入摘要。
5. 原子移动到房间程序目录。
6. 初始化独立数据目录。

### 8.2 启动

1. 确认程序完整性。
2. 检查 SDK 和宿主模块可用性。
3. 执行待处理迁移。
4. 创建沙箱渲染环境和权限上下文。
5. 加载 `room://<id>/app/index.html`。

### 8.3 更新

1. 确认房间 ID 与发布者关系。
2. 对程序、数据库和权限创建检查点。
3. 校验并安装新程序到暂存位置。
4. 展示并确认新增权限。
5. 执行数据库迁移和健康检查。
6. 成功后切换当前版本；失败则回滚。

### 8.4 卸载

程序和数据分开处理。默认卸载程序时保留可恢复数据，只有用户明确选择“同时删除数据”才删除房间数据。

## 9. 完整性与签名

`integrity.json` 对清单声明范围内的每个文件记录相对路径、大小和 SHA-256。哈希清单本身由 `signature.json` 签名。

签名信任建议分为：

1. 工作台官方。
2. 组织管理员信任的发布者。
3. 用户本机创建。
4. 未知或未签名来源。

MVP 是否允许导入未知签名房间由产品策略决定；无论如何，未知来源不得自动获得敏感权限。

## 10. 版本兼容

- `formatVersion`：控制包结构，未知主版本拒绝导入。
- `roomSdk`：控制代码 API；工作台至少支持当前主版本和一个上一主版本，具体周期待 ADR 确认。
- `hostModules`：逐模块声明主版本。
- `minimumWorkbench`：用于新能力的最低版本门槛。
- 工作台升级不得原地修改原始 `.room`；如需转换，应生成新包或内部安装副本。

## 11. 数据快照

数据快照不是 `.room` 的默认组成部分，建议后续定义独立 `.zdata` 格式。快照必须声明对应房间 ID、数据库版本、创建时间、是否加密和包含的敏感数据类型。

导入数据快照不得自动替换现有数据，应提供新建副本、合并或覆盖前备份选项。

## 12. 合规性测试

房间编译器必须提供机器可执行的验证套件：

- 清单 Schema 测试。
- 路径、大小和压缩安全测试。
- 禁止依赖及外部 URL 扫描。
- CSP 和入口文件检查。
- SDK 版本与权限调用一致性检查。
- Windows/Linux 路径大小写和字符兼容测试。
- 数据迁移的空库、旧库、失败回滚测试。
- 可重复打包和哈希一致性测试。

只有通过规范验证的产物才可被标记为“已验证房间”。
