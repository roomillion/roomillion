# 批量 AI 房间平台能力

## 目标

本轮把房间运行时从“小型单次交互 SDK”扩展为可承载批量视觉识别、长文档整理和可恢复流水线的平台。AI Harness 仍负责首次需求与能力边界确认，后续编码和修复由模型自主推进；平台提供能力、权限和测试，不规定业务步骤。

## 能力声明 v2

`room-app@1` 继续兼容 `ai: true`，并支持按角色和槽位声明模型：

```json
{
  "capabilities": {
    "database": true,
    "files": ["pickMany", "directoryRead", "directoryWrite", "export"],
    "ai": {
      "roles": ["vision", "general"],
      "slots": {
        "ocr": { "role": "vision", "requiresImages": true },
        "text-review": { "role": "general", "minimumContextWindow": 128000 }
      }
    },
    "compute": ["worker"],
    "tools": ["document.markdown-to-pdf@1"],
    "credentials": [],
    "network": [],
    "browser": []
  }
}
```

模型槽位由用户选择具体工作台模型。房间代码只保存配置 ID，不读取 API Key。`room.ai.batch()` 支持 1–500 项、1–8 有界并发、0–5 次重试、逐项成功/失败结果，以及 Blob/目录文件形式的图片引用。

## 文件、Blob、制品和任务

- `room.files.pickMany()` 批量选择文件。
- `openDirectory()` 返回不含绝对路径的持久授权 ID；`listDirectory()` 自然排序分页，`readDirectoryFile()`/`writeDirectoryFile()` 只能访问授权根内且拒绝符号链接和路径穿越。
- `room.blobs` 通过 begin/write/finish 分块保存中间二进制或长文本。
- `room.artifacts` 保存最终 Markdown、PDF 等制品，并可写入已授权的输出目录。
- `room.jobs` 持久保存 queued/running/paused/completed/failed/cancelled 状态、进度和检查点；进程中断后 `recover()` 把 running 任务恢复到队列。
- `room.documents.markdownToPdf()` 使用内置 CJK 字体生成分页 PDF 制品。

PDF 当前保留完整的内置 OpenType/CFF 字形并修正字体字典，规避固定版本字体子集器造成的中文方框；每份文件约有 14 MB 字体开销。PDF 验收需要渲染检查，文件头和可提取的 Unicode 文本不能证明字形正确。当前支持基本标题、段落、列表、表格网格与单元格换行分页；跳过元信息/注释和空白尾页，避免页末孤立标题。复杂表格和出版级版式仍需后续改进。

## 本地计算、工具和插件桥

声明 `compute: ["worker"]` 后，房间可从包内同源文件创建 Web Worker，执行排序、Markdown 合并、哈希等 CPU 工作。Worker 仍处于 Chromium 沙箱，不能访问 Node.js、Electron、主机路径、Service Worker 或 SharedWorker。

`room.tools.list()` 和 `room.tools.call(id, input)` 是统一宿主工具桥。房间必须声明并获得每一个工具 ID 的授权。当前内置 `document.markdown-to-pdf@1` 与 `artifact.list@1`；宿主插件可以注册更多处理器，无需扩展通用 IPC，也不会向房间开放插件自身的系统权限。

## 命名凭据

工作台“联网控制”可以保存命名凭据，包括别名、精确服务源、请求头和前缀。勾选持久化时密钥由 Electron `safeStorage` 加密；取消时只保留在当前会话。

房间需要同时声明并获得 `permissions.credentials` 别名与 `permissions.network` 服务源权限。它只能通过 `room.credentials.list()` 查看脱敏状态，并在 `room.network.request/open` 中传 `credentialAlias`。宿主在发送时注入请求头；明文不进入房间、响应、普通配置、诊断日志或 `.room` 包。每次重定向都会重新检查服务源绑定。

## 能力感知测试

批量文件或视觉 AI 房间必须携带 `app/room-tests.json`。一个文件可声明至少 1 个场景（总数不设上限，续改保留旧回归，整轮受隔离运行超时保护）、每个场景 1–100 个动作：`click`、`input`、`wait`、`assertExists`、`assertText`。`mocks.ai` 提供隔离运行时的模型响应，因此测试可以点击真实 AI 按钮并验证界面结果，而不调用外部模型。

Harness 的完成门现在包括静态检查、需求契约、隔离启动、重载、通用按钮探测和声明式业务场景。它仍不能替代真实模型质量、超大数据压力和最终视觉验收。

书籍 OCR Goal 暴露了只有空文件选择模拟时无法覆盖读图路径的问题。声明式测试现支持 `mocks.files` 内联虚构样本：`{name:'page1.png',base64:'...'}` 或 `{name:'sample.csv',text:'...'}`；最多 20 项、合计 2 MiB，仅约束测试样本。运行器在独立临时目录写入样本，复用正式二进制文件和目录服务，提供可选择的视觉模拟模型。`mocks.ai` 响应可附加 `expectedImageCount:1`，防止没有传入图片却通过 OCR 测试。未提供样本时保留取消文件选择行为。

正式房间批量选择后只需 `files.pickMany` 即可通过 `readBinary(token,options)` 读取本房间已选择的文件，不再额外要求 `files.pick`；跨房间令牌和权限撤销仍检查。视觉调用使用 `generate(prompt,{profileId,images:[{data,mimeType}]})` 或 Blob/目录引用；误传 `input`、`model` 时明确提示正确字段，避免静默发送无图请求。

模型取消需向 `generate` 传唯一 `requestId`，再调用 `room.ai.cancel(requestId)`；`AbortSignal` 不能跨 IPC 传递，误传时明确报错。隔离模型的 `chunkDelayMs` 是每三个字符之间的延迟，取消的调用同样消耗一条模拟响应。测试失败应修复根因，不能删除正文、持久化等业务断言来换取通过。

隔离运行器也提供真实的 `room.documents.markdownToPdf(markdown, options)` 和制品读取。默认总时限为 45 秒加声明的等待、重载与点击耗时，最多五分钟；调用方显式时限仍优先。断言错误附带页面上下文，帮助区分真实业务错误、模拟响应不足与等待时序问题。
