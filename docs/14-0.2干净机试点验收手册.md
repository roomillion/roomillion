# 千万间 Roomillion 0.3 Alpha 干净机与内部试点验收手册

## 1. 验收目标

本手册用于完成当前开发机无法替代的两个阶段门：

1. 在未安装开发工具的第二台 Windows x64 电脑验证免安装、离线和自包含。
2. 让 5～20 名非开发内部用户完成真实任务，验证操作文案和成功率。

测试对象固定为：

```text
Roomillion-0.3.0-alpha.3-Portable.exe
SHA-256: B921C9B8C9FEC0503D3E169FA495794FDB64D13236B02BA60E40DB7F8B1E27CF
```

## 2. 干净机要求

- Windows 10/11 x64，使用普通用户账户。
- 未安装 Node.js、npm、Bun、Git、SQLite 和开发 IDE，或确认这些程序不在 PATH。
- 测试目录由普通用户拥有，不使用管理员身份启动。
- 至少 1 GiB 可用磁盘空间。
- 首轮先断开外网；AI 专项再连接指定内网或测试 API。

记录系统版本：运行 `winver`，把版本、OS Build、CPU 架构、杀毒软件名称填入结果表。不要在诊断报告中手工加入用户名、业务数据或密钥。

## 3. 文件校验

推荐直接解压试点验收包并双击 `验证便携版.cmd`。它会自动核对 SHA-256、记录当前进程是否为管理员、检查 PATH 中是否存在 Node/npm/Bun/Git，并在子进程 PATH 仅保留 Windows System32 的条件下运行完整冒烟。冒烟同时拦截并统计 HTTP、HTTPS 和 WebSocket 请求，任何出站尝试都会导致失败。结果写入同目录 `pilot-result.json`，不包含用户名、绝对路径或业务数据。

自动结果为 `PASS` 后，仍必须继续完成本手册的断网、SmartScreen/杀毒软件和真实用户任务；脚本无法替代这些人工证据。

也可以手工执行：

在 PowerShell 中执行：

```powershell
Get-FileHash -Algorithm SHA256 .\Roomillion-0.3.0-alpha.3-Portable.exe
```

结果必须与本手册顶部一致。哈希不一致时停止测试并重新取得文件。

## 4. 离线自包含验收

1. 断开网络，双击便携版；不得请求 UAC 管理员权限。
2. 点击“安装示例”，打开“物资台账”。
3. 新增两条记录，关闭标签并重新打开，确认记录仍存在。
4. 打开“详情”，确认能看到 `git version 2.55.0.windows.3` 和至少一个版本检查点。
5. 创建手动检查点；不得弹出终端或要求安装 Git。
6. 导出 `.room`，关闭应用后重新启动并导入；必须先出现安全预检，不得直接安装。
7. 只勾选私有数据库，安装后在“详情”中确认文件和 AI 权限未授予。
8. 全程观察是否出现联网下载、缺 DLL、缺 Git/Node 或命令行窗口。

任意一项失败都属于发布阻断问题。

## 5. 数据备份恢复验收

1. 在示例房间准备三条容易识别但不含真实敏感信息的测试记录。
2. 点击“备份数据”，设置至少 8 位测试密码，导出 `.zdata`。
3. 修改或删除记录。
4. 点击“恢复数据”，先输入错误密码；当前数据必须保持不变。
5. 再次输入正确密码；数据恢复为备份时状态。
6. 确认房间程序版本和权限没有因数据恢复改变。
7. 把 `.zdata` 复制到另一测试账户或另一台已安装同一房间的工作台，完成跨环境恢复。

不得使用真实业务密码和真实生产数据测试预览版。

## 6. 程序版本回退验收

1. 配置测试 AI，选择“记住密钥”，关闭并重启工作台，确认无需重新输入即可测试连接。
2. AI 创建一个会议事项台账。
3. 新增一条记录。
4. 使用“AI 修改”增加负责人和完成日期字段。
5. 在“详情”查看“AI 修改前”和“AI 修改完成”检查点。
6. 恢复到修改前检查点：字段应回退，之前新增的业务记录仍在数据库中。
7. 再恢复到修改后检查点，确认程序可再次前进。

只允许使用测试 API Key；测试结束后点击“清除密钥”。

## 7. 权限和诊断验收

1. 在“详情”撤销导出文件权限，不重启房间直接尝试导出；必须立即被拒绝。
2. 重新授权后再次导出，应恢复正常。
3. 点击“导出诊断报告”。
4. 用文本编辑器检查报告：不得出现 API Key、备份密码、测试记录正文、用户名、绝对路径或完整内网 URL。
5. 报告应包含应用/Electron/Git 版本、房间 ID/版本、权限键和脱敏事件。

## 8. 试点用户任务

每位用户独立完成以下任务，不由开发者代点：

- 安装示例并新增记录。
- 看懂一次外部房间导入预检并选择权限。
- 备份并恢复数据。
- 创建检查点并恢复房间程序。
- 配置测试 AI 并生成一个台账。
- 导出脱敏诊断报告。

记录完成/失败、耗时、是否需要帮助和用户原话。不要只记录“感觉不错”。推荐每位用户完成后双击验收包中的 `试点反馈表.html`，使用匿名编号填写并导出 JSON；页面全程离线，不自动上传。

## 10. 阶段通过标准

试点负责人收齐 5～20 份反馈 JSON 后，双击 `汇总试点结果.html` 并一次选择全部文件。页面会计算阶段指标、拒绝重复测试人编号并导出 `zhibian-pilot-summary.json`。原始反馈与汇总均应保留在受控的内部项目目录。

- 至少两套独立 Windows 用户环境完成离线验收。
- 首次成功启动率不低于 95%。
- 示例安装、备份恢复和程序回退成功率分别不低于 95%。
- 失败修改恢复旧版本成功率为 100%。
- 不看开发文档完成示例安装的比例不低于 90%。
- 没有明文密钥、原数据覆盖、权限绕过或未知联网下载。

未达到标准时继续修复 `0.2.x`，不得仅凭个别成功截图进入 UOS/Linux 阶段。
