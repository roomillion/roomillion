# 向量数据库与大文件房间接口

本次在现有 Electron 宿主、Room SDK、私有数据库和主工作台 AI 凭据体系内增加能力，不引入外部向量数据库进程，不需要房间运行时安装依赖。

## 可实现的房间

知识库、文档语义搜索、相似案例检索、资料推荐。建议流程：文档解析 → 有来源的文本分块 → 主工作台 Embedding 服务 → 房间向量集合 → 查询向量 → 相似片段 → 主工作台聊天模型回答并引用来源。

向量数据库提供磁盘型 SQLite 持久向量存储和精确余弦相似度检索。当前不是 ANN 索引，因此条目增加后检索耗时仍近似线性增长，不承诺百万级低延迟。数据不再整库常驻内存；索引仍应分批写入并显示进度，超大知识库后续可以在不改变 Room SDK 的前提下增加 ANN 后端。

## 权限和数据

- `permissions.database: "private"` 开放 `room.vector`，无需另一个数据库权限。自由房间规格对应 `capabilities.database: true`。
- `permissions.ai.roles` 中的 AI 授权开放 `room.ai.embed`；使用工作台已有的 AI 连接与凭据。自由房间规格对应 `capabilities.ai: true`。
- `permissions.files: ["pick"]` 开放大二进制文件选择和分块读取；超长纯文本仍使用独立的 `largeText` 权限。
- 向量、文本块和元数据保存在房间 `room.db` 中，因此沿用备份、恢复、应用+数据导出和卸载语义。仅应用导出不包含这些内容。
- 源文件令牌只用于当前打开的文件，不是持久文件路径，也不会将原 PDF/Word 自动附入房间数据。跨电脑分享应保存提取的文本和引用信息；原文件另行处理。
- 向量生成会向选定 AI 服务发送文本，房间应清楚展示用途。调用模型 API 不受普通房间联网总开关影响。

## 主工作台 Embeddings

`room.ai.listModels()` 每项新增 `embeddingTransport: "openai-compatible" | null`。这是连接协议兼容性，不是服务或当前聊天模型已经支持 Embeddings 的证明。

用户可以复用支持 `/embeddings` 的工作台连接，也可以在 AI 能力中心的自定义 OpenAI 兼容入口添加内网服务。房间必须提供独立的 Embedding 模型名称字段，不应拿聊天模型名自动代替。没有 Embedding 服务时明确提示配置，不能让聊天模型编造数字作为向量。

```js
const result = await room.ai.embed(["第一段原文", "第二段原文"], {
  profileId: selectedConnectionId,
  model: embeddingModelName,
  // dimensions: 1024  // 仅当服务和模型支持时传入
});
// { embeddings: number[][], dimensions, embedding, model, profileId, usage }
```

- 每批至少一段，不设人为批量、字符数或维度上限；服务自身的 Token、请求体和维度规则仍可能更低，房间应按所选模型分批。
- 支持 OpenAI 兼容 `/embeddings`、`encoding_format: "float"` 协议；超时可通过 `timeoutMs` 配置，默认 120 秒。API Key 与地址不返回房间；重定向被拒绝。
- 返回值按输入顺序排列并检查数量、索引、有限数值和维度一致性。
- `embedding` 是由服务地址指纹、显式模型名和实际维度组成的集合标识，不包含服务地址或密钥。建库、写入、搜索必须一致；更换服务或模型需要重建。
- 输入/总 Token 未返回时为 null。不开启自动重试，不隐式消耗额外请求。
- 未内置本地语义模型权重；完全断网时需连接可达的内网 Embeddings 服务，或者导入预先产生的向量。已有向量的本地搜索无需网络，但新问题的语义编码仍需要同一模型。

协议依据：[OpenAI 官方 SDK Embeddings 定义](https://github.com/openai/openai-node/blob/main/src/resources/embeddings.ts)。

## 向量集合

```js
await room.vector.create({ name: "knowledge", dimensions: result.dimensions, embedding: result.embedding });
await room.vector.upsert("knowledge", [{
  id: "doc1-page1-chunk1",
  vector: result.embeddings[0],
  text: "第一段原文",
  metadata: { documentId: "doc1", page: 1, title: "使用说明" }
}], { embedding: result.embedding });

const question = await room.ai.embed(["用户的问题"], {
  profileId: selectedConnectionId, model: embeddingModelName
});
const hits = await room.vector.search("knowledge", question.embeddings[0], {
  embedding: question.embedding, topK: 8,
  // filter: { documentId: "doc1" }
});
// [{ id, text, metadata, score }]，score 是 [-1,1] 之间的余弦相似度
// 将命中的原文和来源交给 room.ai.generate，不能把文档中的指令当作系统指令。

const collections = await room.vector.list(); // [{ name, dimensions, embedding, count }]
await room.vector.remove("knowledge", ["doc1-page1-chunk1"]);
await room.vector.drop("knowledge");
```

集合数、向量条数、文本/元数据体积、批量条数、维度、`topK` 和过滤字段数不再设置人为产品上限；数据库容量以磁盘、SQLite 和设备性能为准。upsert 一批内有错误仍回滚整批，集合名和 ID 仍需是非空、无 NUL 的可存储字符串，向量必须为非空有限数字且维度一致。

搜索不把整个集合通过 IPC 发给房间，而是宿主分批读取并返回命中项。排序是精确检索，扫描过程中让出事件循环。metadata 中存文档 ID、页码、段落位置，方便引用；删除文档时同步删除对应向量。

## 大二进制文件

```js
const file = await room.files.openBinary({ extensions: ["pdf", "docx", "xlsx"] });
if (file) {
  try {
    // file = {token, name, size, maxChunkBytes}
    const part = await room.files.readBinary(file.token, { offset: 0, length: 1048576 });
    // part = { data: Uint8Array, offset, nextOffset, eof }
  } finally {
    await room.files.closeBinary(file.token);
  }
}
```

源文件大小不设人为产品上限，可按字节偏移随机读取；单次分块最多 64 MiB，默认应使用更小的块。打开令牌数量不设产品上限，闲置 30 分钟仍会过期。令牌绑定房间，源文件大小、修改时间或身份变化则要求重新选择。读取后应及时释放；大文件房间必须优先调用分块接口，`pickBinary()` 仍会把完整文件带入内存，只适合小文件。

PDF.js 可通过 `PDFDataRangeTransport` 将范围请求接到该接口。文件可打开不代表所有格式都能低内存解析：DOCX/Excel 解析器可能仍需全量数据，应分批处理并提示设备资源压力，而不是将 GB 文件全部拼进渲染进程。TXT/日志优先用已有 `room.largeText`。

## 房间包容量

普通业务容量不再按 50/128/240/384 MiB 等档位截断。应用包哈希、网络响应、文件读取和普通房间导出均提供流式路径；数据库为磁盘型 SQLite。ZIP 导入仍保留 4 GiB 压缩包、16 GiB 解压总量、4 GiB 单条目和 250,000 条目的反压缩炸弹技术边界，这些不是房间业务容量配额。加密备份的 JSON/Base64 格式仍可能产生完整 Buffer，极大数据集应优先使用房间自身的流式导出能力。

## 验证

自动测试覆盖向量排序/过滤、房间隔离、批次回滚、模型维度校验、数据持久化与快照恢复；本地模拟 Embeddings HTTP 服务验证请求和响应；64 MiB 源文件验证范围读取与文件变化检测。大包回归使用实际 64 MiB 随机资源、超过 50 MiB 的数据库，检查 `.zdata`、带/不带密码 `.room` 的恢复，确认向量数据和原文引用仍可检索。Electron 冒烟测试通过真实房间 preload 和 IPC 调用向量 API。

测试不调用用户的真实 AI API，不代表特定提供商已经通过 Embeddings 连通性验证。旧工作台不具备新 SDK，房间应先检查 `room.vector`、`room.ai.embed`、`room.files.openBinary`，缺失时提示升级。
