# 千万间 Roomillion：发布前评审与 GitHub 清单

评审日期：2026-09-09。对象：当前 Windows x64 源码工作区，版本标识 `0.3.0-alpha.25`。本轮仅评审、运行隔离测试和生成报告，没有修改产品代码、打包或上传 GitHub。

## 1. 评审范围与证据边界

- **Computer Use 部分受阻**：能枚举窗口、读取主页的可访问性元素，但截图为黑屏，激活窗口与点击“AI 创建房间”返回 `GetCursorPos failed: 拒绝访问。(0x80070005)`。刷新窗口选择后重试仍失败，因此未完成鼠标操作的端到端验收，也不能评价本轮截图的视觉细节。
- 依照当时使用的 computer-use 技能恢复规则，状态捕获或激活失败时重新选择窗口、重试一次，并在恢复失败后报告准确错误。没有绕过系统输入权限。
- **实际 AI 调用**：改用生产 `RoomAgentService`、`AiService` 和内置 MinGit，调用已配置的 MiMo Token Plan / `mimo-v2.5`。房间和对话保存在独立评审目录，不写入用户现有房间库。此项是服务链路测试，不冒称 Computer Use 点击成功。
- **代码检查**：检查 Agent、权限、版本兼容、主页、提供商配置、构建、许可证与仓库状态。
- **自动化回归**：本轮 `npm test`，141/141 通过。该结果不等于真实模型生成出的任意房间都正确。

## 2. 真实模型测试

原始需求：“我想做一个家庭图书借阅管理的小工具。”

补充回答：个人在家管理借给亲友的书；300 本书、1000 条以内借阅记录；从空白手工录入；书名、作者、借阅人、借出日期、应还日期、归还状态；借出、归还、搜索、未还/逾期统计、CSV 导出；本地保存，不联网、不调用 AI。

| 阶段 | 本轮观察 |
| --- | --- |
| 简单需求 | 约 22 秒，提出 4 个问题，未创建房间 |
| 澄清回答 | 约 38 秒，提交 8 栏方案，未创建房间 |
| 确认实施 | 约 299 秒后在评审总时限处停止，未创建房间；首次草稿因无效 JSON 失败，修复请求在停止时仍未完成 |

正向结果：需求澄清与批准门槛真实生效。问题附有推荐项和贴合家庭场景的例子，模型没有要求使用者选择技术栈。

暴露的问题：功能题是递进的单选项，“统计”需要选“全都要”；第 4 题优先问图书分类，没有先问初始数据如何进入工具。方案把 CSV 导出描述为备份，但只导出借阅记录并不等于可以恢复全部书目和关系。返回内容出现 Markdown 与字面量 `\\n`；当前展示函数是 `textContent`，不会格式化 Markdown 或将字面量转义序列变成换行。

本地过程证据：`release/review-2026-09-09/agent-result.json`。测试目录已由现有 `release/` 规则忽略，不应作为源码发布内容。

### 最终生成结果及用量

- 首次 `draft_custom_room` 的 `appSpecJson` 长 35,255 字符，JSON 解析在位置 18,254 失败，报错 `Expected ',' or '}' after property value`。模型结束原因为 `toolUse`，没有证据表明该首次输出被 Token 上限截断。
- 工具拒绝了无效草稿，未进入测试或安装。模型开始第二次草拟；评审脚本在全流程 360 秒的预设总时限调用了停止。**这个停止是本次测试限制，不是已证实的产品超时或模型永远不能完成。**
- 已返回用量合计 51,679 Token：输入 23,430、输出 12,825、缓存读取 15,424。中断请求的零用量回传不能证明其不收费；实际用量和订阅额度扣减以提供商账单为准。
- 没有生成可打开的房间，因此本轮没有完成新房间运行验收。141 项回归通过与这个真实模型样本失败应分别记录，不能互相替代，也不能凭单个样本估算整体成功率。
- 初始化隔离评审进程时曾因使用了不同的安全存储上下文而无法解密凭据；切换为工作台自身加密上下文后调用成功。没有修改或重存现有密钥，这不构成正常工作台密钥损坏的证据。

## 3. 十条改进建议

P1 表示建议公开测试前优先处理；P2 表示可列入下一小版本。以下不是已经实施的修改。

| # | 优先级 | 建议 | 依据与验收方式 |
| --- | --- | --- | --- |
| 1 | P1 | **拆分自由房间写入，避免双重 JSON 编码** | 本轮 35,255 字符的 `appSpecJson` 首次解析失败，之后整份重写。改为结构化 manifest + 按文件写入/更新，再独立校验与打包；每次错误返回文件、行列和简短定位。保留现有安全约束，不以宽松执行模型文本来“修复 JSON”。 |
| 2 | P1 | **让生成进度和成本可控** | 本轮数分钟没有新工具步骤；`handleAgentEvent` 仅展示 `text_delta`，没有工具参数流进度。展示当前阶段、最后响应时间和停止入口；在已有逐轮用量统计上增加任务累计预算、修复次数上限和“简版优先”，不显示虚假的百分比。 |
| 3 | P1 | **把“静态检查通过”和“运行验收通过”分开** | `test_custom_room` 调用静态分析和正则契约；检查有事件监听并不证明“归还”按钮正确。安装前增加隔离启动、控制台/未处理异常检测、借出→归还→重开持久化测试；明确哪些需求仍待人工验收。 |
| 4 | P1 | **安全格式化方案与聊天内容** | 本轮方案含 `**`、Markdown 表格、字面量 `\\n`，页面按纯文本渲染。统一生成字段格式，正确呈现段落、列表和表格；如采用 Markdown，必须经过已内置的净化器，不直接注入模型 HTML。 |
| 5 | P1 | **中断后保留可恢复的草稿** | `acceptMessage` 对普通后续消息直接将 `customDraft` 清空。区分补充需求、重试、继续制作；将已通过静态检查的草稿做版本化保存，重试基于上次进度，不强迫从头输出整份代码。 |
| 6 | P1 | **提供商状态不要一律叫“已连接”** | `renderProviderProfiles` 中标识无条件写“已连接”。区分已配置、密钥可读取、未测试、最近验证成功、验证失败，并显示验证时间；不可因本轮测试采用错误的隔离加密上下文就断言正常应用密钥损坏。 |
| 7 | P1 | **真正校验最低工作台版本与能力依赖** | `minimumWorkbench` 当前仅做字符串校验；自由房间生成仍填 `alpha.1`。向量库、大文件或新版接口房间应声明实际需要的能力，导入时拦截旧工作台并给出升级说明，避免打开才报 undefined。 |
| 8 | P2 | **功能问答支持多选，并优先询问高影响问题** | 本轮“除了借还还需要什么”使用递进单选；需要搜索但不需要提醒时选择不自然。使用者、初始数据来源/规模优先，独立功能用多选，轻量偏好如书目分类可放到可选项。 |
| 9 | P2 | **明确区分导出报表与可恢复备份** | 本轮方案称“可通过 CSV 导出做备份”，但 CSV 仅含借阅记录。方案应说明数据覆盖范围，提供跳转工作台完整备份的入口；验收时确认空闲图书、借阅关系、历史状态均可恢复。 |
| 10 | P2 | **主页增加搜索、最近使用与收藏** | 本轮可访问性树列出 9 张房间卡片，未见主页搜索/排序/收藏入口。房间增长到几十个后，应能按名称搜索、按最近使用排序，并保留少量收藏；主页无活动房间时可隐藏无关的禁用操作。 |

代码证据集中于：`src/main/room-agent-service.cjs`、`src/renderer/app.js`、`src/main/manifest.cjs`、`src/main/custom-room.cjs`。本轮未实际鼠标验证的菜单、窗口拖动、图片上传、导出密码等操作不能据此宣称通过。
