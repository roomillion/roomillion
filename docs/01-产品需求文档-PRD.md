# 千万间 Roomillion产品需求文档（PRD）

## 1. 文档信息

- 版本：`0.1-draft`
- 状态：立项评审稿
- 产品：千万间 Roomillion
- 核心产物：房间包 `.room`

## 2. 产品目标

让不具备完整开发和部署能力的用户，也能通过 AI 创建、运行和分享具有本地数据、文件处理及 AI 能力的小型应用，同时不需要安装开发环境、访问公网包源或理解跨平台打包。

## 3. 关键术语

| 术语 | 定义 |
|---|---|
| 工作台 | 安装在用户设备上的桌面宿主程序，负责创建、运行、隔离和管理房间 |
| 房间 | 符合统一规范、在工作台内运行的小程序 |
| Room SDK | 房间访问数据库、文件、AI、任务等宿主能力的唯一接口 |
| 房间包 | 可分享的单文件应用包，暂定扩展名 `.room` |
| 房间数据 | 使用过程中产生的数据库、文件、设置和缓存，不默认包含在房间包中 |
| AI Gateway | 工作台统一管理各种 AI Provider、密钥、调用权限和审计的内部服务 |
| 官方能力 | 随工作台发布、无需房间自行下载的组件和服务 |

## 4. 核心用户旅程

### 4.1 创建房间

1. 用户点击“新建房间”。
2. 用户用自然语言描述需求，也可以选择模板和导入示例文件。
3. 工作台展示 AI 对需求的理解、准备使用的能力和需要申请的权限。
4. AI 在受限房间工程中生成代码。
5. 系统自动构建、静态检查、运行测试并打开预览。
6. 用户在预览中提出修改，AI 继续迭代。
7. 用户保存房间版本或导出 `.room`。

### 4.2 接收和使用房间

1. 用户把 `.room` 拖入工作台。
2. 工作台检查格式版本、完整性、签名、权限和兼容性。
3. 工作台显示房间来源、所需权限和是否包含额外依赖。
4. 用户确认后导入。
5. 房间在独立标签中打开，并创建自己的数据空间。

### 4.3 配置 AI

1. 用户打开“AI 能力中心”。
2. 选择预置服务商或“OpenAI-compatible/内网服务”。
3. 填写 API 地址、密钥和模型，点击“测试连接”。
4. 工作台检测流式输出、工具调用、视觉和推理能力。
5. 用户设置默认编程、通用和视觉模型。
6. 房间只引用逻辑模型名称，不接触真实密钥。

### 4.4 更新房间

1. 用户导入同一房间的新版本。
2. 工作台展示版本变化、权限变化和数据迁移。
3. 工作台备份现有数据后更新程序。
4. 更新失败则回滚程序和数据库迁移。

## 5. 功能需求

优先级定义：P0 为 MVP 必须完成；P1 为试点需要；P2 为后续增强。

### 5.1 工作台与房间管理

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-001 | 新建、打开、关闭、重命名和删除房间 | P0 | 无需文件管理器或命令行 |
| FR-002 | 以标签方式切换多个房间 | P0 | 一个房间异常不导致全部房间数据损坏 |
| FR-003 | 导入、导出 `.room` | P0 | 离线设备之间可复制使用 |
| FR-004 | 显示房间版本、来源、权限和签名状态 | P0 | 导入前可查看 |
| FR-005 | 房间更新、备份和失败回滚 | P0 | 更新失败保留原版本和数据 |
| FR-006 | 房间模板库 | P1 | 离线内置至少 10 个代表模板 |
| FR-007 | 组织房间目录和离线分发库 | P2 | 管理员可审核和发布 |

### 5.2 AI 创建体验

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-101 | 自然语言创建和修改房间 | P0 | 用户无需选择技术栈 |
| FR-102 | AI 只能使用工作台允许的工具 | P0 | 默认没有任意 Bash/npm/宿主文件权限 |
| FR-103 | 自动构建、检查、测试和预览 | P0 | 失败信息可回传给 AI 修复 |
| FR-104 | 在申请新增权限前说明用途 | P0 | 用户可以拒绝 |
| FR-105 | 保存会话、版本和修改历史 | P0 | 可以恢复到已知可用版本 |
| FR-106 | 引用 Room SDK 与组件文档 | P0 | AI 使用的 API 与当前运行时匹配 |
| FR-107 | 对本地小模型提供精简提示和确定性模板 | P1 | 基础 CRUD 房间可由内网模型完成 |

### 5.3 AI 能力中心

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-201 | 接入 Pi 的统一 Provider 层 | P0 | Provider 与 Agent UI 解耦 |
| FR-202 | 支持预置主流 API 和 OpenAI-compatible 自定义端点 | P0 | 可连接云 API 和内网推理服务 |
| FR-203 | 测试连接并展示模型能力 | P0 | 错误区分网络、认证、模型与协议问题 |
| FR-204 | 密钥安全保存，房间不可读取 | P0 | 日志和导出包不包含明文密钥 |
| FR-205 | 设置编程、通用、视觉等默认模型 | P0 | 房间通过逻辑角色使用模型 |
| FR-206 | 每房间 AI 权限和用量统计 | P1 | 可禁用、限额和查看调用记录 |
| FR-207 | 管理员离线下发 Provider 模板和内网证书 | P1 | 模板默认不携带个人密钥 |

### 5.4 数据和文件

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-301 | 每个房间独立 SQLite 数据空间 | P0 | 房间不能访问其他房间数据库 |
| FR-302 | 房间私有文件目录 | P0 | 路径不能逃逸到宿主其他位置 |
| FR-303 | 用户通过文件选择器授权外部文件 | P0 | 房间不能直接传入任意绝对路径 |
| FR-304 | 导入导出 CSV、JSON 和常用图片 | P0 | 无需外部包 |
| FR-305 | Excel、PDF、Markdown 等标准能力 | P1 | 由工作台能力提供并版本化 |
| FR-306 | 程序包与数据快照分别导出 | P0 | 普通房间分享不带用户数据 |
| FR-307 | 数据迁移和回滚 | P0 | 更新过程具备事务性或可恢复性 |

### 5.5 Git 与版本管理

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-401 | 工作台使用内置 Git，不依赖系统 Git | P0 | 清空 PATH 后仍可工作 |
| FR-402 | AI 可执行受控的 status、diff、commit、branch | P0 | 不暴露任意 Git 参数执行器 |
| FR-403 | 每次 AI 修改前后形成可恢复检查点 | P0 | 用户可以恢复稳定版本 |
| FR-404 | clone、fetch、pull、push 需要网络权限和确认 | P1 | 离线模式下明确禁用 |
| FR-405 | 默认禁用 hooks、危险协议和自动子模块 | P0 | 导入仓库不自动执行代码 |

### 5.6 分发与更新

| 编号 | 需求 | 优先级 | 验收摘要 |
|---|---|---|---|
| FR-501 | Windows 无管理员用户安装包 | P0 | 普通用户可以安装和卸载 |
| FR-502 | Windows 便携目录包 | P0 | 解压后直接运行 |
| FR-503 | UOS/Linux AppImage 或等价便携包 | P0 | 不通过系统包管理器安装 |
| FR-504 | UOS/Linux 解压目录版作为兼容兜底 | P0 | FUSE 不可用时仍有路径运行 |
| FR-505 | 安装包内置 Electron、Pi、Bun、Git、SQLite 和标准资源 | P0 | 首次启动不下载运行依赖 |

| FR-507 | 生成第三方许可证和组件清单 | P0 | 可追溯内置组件版本 |

## 6. 非功能需求

### 6.1 安全

- 房间渲染环境关闭 Node 集成，开启上下文隔离和进程沙箱。
- 房间只能通过经过参数校验的 IPC/Room SDK 请求宿主能力。
- 网络默认关闭；AI 请求只通过 AI Gateway。
- API Key 不进入房间、Git 历史、诊断日志或普通导出包。
- 导入包必须执行路径穿越、压缩炸弹、哈希和清单检查。
- 房间权限变更必须重新确认。

### 6.2 离线性

- 首次运行和创建基础房间不访问公网包源。
- 构建过程不执行 `npm install`。
- 官方能力和模型元数据随工作台提供。
- 在线功能不可用时，不影响已导入房间的本地能力。

### 6.3 兼容性

- 以明确的“操作系统版本 + CPU + 工作台版本”矩阵发布支持结论。
- `.room` 不得包含平台专属原生模块。
- Room SDK 采用版本化接口，并规定兼容和迁移周期。

### 6.4 可恢复性

- 房间更新、数据库迁移和 AI 大规模修改前创建检查点。
- 工作台异常退出后能够识别未完成事务并恢复。
- 诊断包可由用户主动导出，默认脱敏。

### 6.5 易用性

- MVP 核心路径不要求使用终端。
- 权限提示使用业务语言，例如“读取你选择的 Excel 文件”，而不是只显示底层 API 名称。
- 错误信息同时提供用户解释和可供 AI/技术人员使用的诊断码。

## 7. 核心页面

1. 工作台首页：最近房间、新建、导入、模板。
2. 房间标签区：运行界面、状态、关闭与恢复。
3. AI 创建区：对话、变更摘要、构建状态、预览。
4. AI 能力中心：Provider、模型、密钥、连接测试。
5. 房间详情：版本、权限、数据、签名、更新和导出。
6. 设置与诊断：运行时版本、离线模式、证书、日志和支持矩阵。

## 8. MVP 验收场景

至少用以下房间完成端到端验收：

1. 个人台账：增删改查、筛选和 CSV 导出。
2. Excel 数据查看器：选择文件、解析、图表和保存视图。
3. AI 文档助手：选择文档、调用用户模型、保存处理结果。
4. 图片资料整理：选择图片、填写标签、SQLite 检索。
5. 完全离线表单：无 AI、无网络仍可正常使用。

每个场景都要完成创建、运行、导出、另一台机器导入、更新和数据保留测试。

## 9. 待产品确认

- 第一批试点用户和最常见的三个真实业务场景。
- 是否允许未签名房间，以及默认提示强度。
- 便携模式是否允许在程序目录保存 API Key。
- MVP 是否必须支持 OAuth 登录，还是先支持 API Key 和内网地址。
- 首批认证的 UOS 版本、桌面环境和 CPU 架构。
- 房间数据快照是否允许包含敏感数据，以及相应的加密策略。
