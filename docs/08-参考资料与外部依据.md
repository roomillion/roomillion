# 千万间 Roomillion参考资料与外部依据

## 1. 使用说明

本文件记录文档基线中的主要外部技术依据，便于立项和架构评审复核。外部项目会持续变化，正式开发时必须锁定具体版本，并以该版本文档和源码为准。

- 整理日期：2026-08-28
- 原则：优先引用官方文档、官方仓库和上游项目说明
- 注意：本索引不是许可证法律意见，也不替代目标平台实机验证

## 2. Pi Agent 与 AI Provider

- [Pi Agent Harness 官方仓库](https://github.com/earendil-works/pi-mono)：Pi 的核心包、Agent、AI Provider 和开发说明。
- [Pi Coding Agent](https://github.com/earendil-works/pi-mono/tree/main/packages/coding-agent)：SDK、会话、工具和扩展能力的入口。
- [Pi 自定义 Provider](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/custom-provider.md)：注册自定义服务、OpenAI-compatible 接口、模型能力和兼容参数。

对应项目判断：使用 Pi 的 Provider 与 Agent 基础能力，但通过 `PiAdapter` 隔离版本变化，并用工作台受控工具替代默认无限制工具。

## 3. Bun

- [Bun 单文件可执行程序](https://bun.sh/docs/bundler/executables)：Bun 可将运行时和资源编译进目标平台可执行程序，也支持指定目标平台构建。
- [Bun Bundler](https://bun.sh/docs/bundler)：TypeScript/JavaScript 构建能力。
- [Bun 全局缓存](https://bun.sh/docs/pm/global-cache)：依赖缓存行为。
- [Bun 配置与离线安装](https://bun.sh/docs/runtime/bunfig)：包管理离线选项等配置。

对应项目判断：Bun适合作为随工作台提供的房间构建器，但目标平台可执行文件不等于跨平台房间包，Bun 也不承担不可信代码的安全隔离。

## 4. Electron 与桌面安全

- [Electron 简介](https://www.electronjs.org/docs/latest/)：Electron 自带 Chromium 和 Node，并面向 Windows、macOS、Linux 构建桌面应用。
- [Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)：主进程、渲染进程和 Utility Process 的职责。
- [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)：Node 集成、上下文隔离、CSP、IPC 校验和不可信内容注意事项。
- [Electron 进程沙箱](https://www.electronjs.org/docs/latest/tutorial/sandbox)：沙箱渲染进程的能力边界。
- [Electron 应用分发](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)：打包、签名、发布和更新概览。

对应项目判断：Electron 是 MVP 候选而不是未经验证的最终结论；必须在指定 UOS 环境实测，并保持房间 Node 集成关闭、上下文隔离和进程沙箱开启。

## 5. SQLite

- [SQLite 单文件跨平台数据库](https://www.sqlite.org/onefile.html)：SQLite 数据库文件的单文件、跨架构和向后兼容特性。
- [SQLite 网络文件系统注意事项](https://www.sqlite.org/useovernet.html)：不建议多台机器通过网络文件系统直接并发读写同一个 SQLite 文件的原因。

对应项目判断：每个房间使用本机独立 SQLite；跨设备分享程序与数据快照分开，多用户集中数据应使用单独的服务端数据源。

## 6. Git 与 MinGit

- [Git for Windows 官方仓库](https://github.com/git-for-windows/git)：Windows Git 的上游项目和安全信息。
- [Git for Windows 构建与 MinGit 说明](https://github.com/git-for-windows/build-extra)：MinGit、PortableGit、组件及许可证信息。
- [Git for Windows 发布说明](https://github.com/git-for-windows/build-extra/blob/main/ReleaseNotes.md)：版本变化、安全修复和组件许可证提示。

对应项目判断：Windows 默认评估为第三方应用内嵌而设计的 MinGit，而不是完整 Git Bash；Git 只通过受控工具使用，并纳入安全更新、SBOM 和许可证流程。

## 7. Linux 便携分发

- [AppImage 运行方式](https://docs.appimage.org/user-guide/run-appimages.html)：无需传统安装的运行和提取方式。
- [AppImage FUSE 问题与替代运行](https://docs.appimage.org/user-guide/troubleshooting/fuse.html)：FUSE 不可用时的提取和运行方案。
- [AppImage 架构](https://docs.appimage.org/reference/architecture.html)：AppImage 自挂载和 AppDir 的基本模型。

对应项目判断：AppImage 可作为单文件 Linux 便携发行物，但必须同时提供解压目录版，并在指定 UOS 版本验证基础库和 Chromium 沙箱。

## 8. WebAssembly 扩展方向

- [WebAssembly Component Model 的设计目的](https://component-model.bytecodealliance.org/design/why-component-model.html)：跨架构、跨语言的组件及接口模型。
- [Component Model 概念](https://component-model.bytecodealliance.org/design/component-model-concepts.html)：组件、接口、WASI 和宿主平台概念。
- [Wasmtime WASI 文件系统权限](https://docs.wasmtime.dev/api/wasmtime_wasi/struct.WasiCtxBuilder.html)：通过预打开目录限制文件系统访问。

对应项目判断：WASM Component 是后续可移植高性能扩展候选，不应阻塞 MVP；引入前需要单独定义 WIT 能力接口和资源限制。

## 9. 复核清单

在锁定 MVP 技术版本时重新确认：

- [ ] Pi 的包名、许可证、Node 版本要求、Provider 和 SDK 接口。
- [ ] Bun 在目标 Windows/UOS 架构上的官方构建和许可证。
- [ ] Electron 目标版本对应 Chromium/Node 版本及安全支持周期。
- [ ] Git/MinGit 内含组件、许可证义务和最新安全公告。
- [ ] SQLite 编译选项、扩展开关和数据库格式策略。
- [ ] AppImage 或目录包在每台认证设备上的实际行为。
- [ ] 所有下载制品的来源 URL、版本、SHA-256 和离线归档。
