# 千万间 Roomillion离线分发与跨平台方案

## 1. 发布目标

对用户的正式承诺建议表述为：

> 无需联网、无需管理员权限、无需额外安装 Node、Bun、Git、数据库或开发工具。

不应表述为“不依赖操作系统任何文件”。桌面程序仍然依赖操作系统内核、图形栈、驱动和基础系统库。

## 2. 发行物矩阵

| 平台 | 发行物 | 是否需要管理员 | 用途 |
|---|---|---:|---|
| Windows x64 | 单文件用户安装包 `Workbench-Setup.exe` | 否 | 日常使用、快捷方式、易卸载 |
| Windows x64 | `Workbench-Portable.zip` | 否 | U 盘、临时设备、禁止安装环境 |
| 指定 UOS/Linux x64 | `Workbench.AppImage` | 否 | 单文件便携运行 |
| 指定 UOS/Linux x64 | `Workbench-linux-x64.tar.xz` | 否 | FUSE 不可用时解压运行；当前构建器原生支持 |
| Windows/Linux ARM64 | 对应架构发行物 | 否 | 在明确需求和测试设备具备后提供 |

安装包按操作系统和 CPU 分开，但其中携带的房间标准一致。不得承诺一个工作台可执行文件跨所有平台。

## 3. 自包含内容

每个平台发行物必须包含：

- Electron、Chromium 和 Electron 自带 Node 运行时。
- 工作台主程序与静态资源。
- Pi Agent/AI 所需 JavaScript 依赖和内置 Provider 元数据。
- 平台对应的 Bun 可执行程序。
- Windows MinGit 或目标 Linux Git 及所需库。
- SQLite 引擎。
- Room SDK、官方组件、模板和帮助文档。
- 默认 CA 证书能力及内网证书导入功能。
- 第三方许可证、版本清单和 SBOM。
- 安装、卸载、修复和诊断所需资源。

本地大模型权重不属于默认安装包。工作台连接已有内网推理服务；如未来提供模型整包，应作为独立、可校验的离线资源包。

## 4. Windows 用户安装版

### 4.1 行为

- 使用 per-user 安装范围，目标位于当前用户可写目录。
- 不写系统级 PATH，不安装系统服务，不注册全局 Node/Bun/Git。
- 快捷方式、文件关联和开机启动均应可选。
- 更新写入用户目录，不触发 UAC。
- 卸载时询问是否保留房间数据和凭据。

### 4.2 单一安装包

`Setup.exe` 可以是单个自包含安装文件，安装后允许展开为多个程序文件。Electron/Chromium、Bun 和 Git 不适合强行保持为运行时单文件。

### 4.3 数据位置

安装版默认将数据放在用户数据目录，而不是程序安装目录。程序升级与房间数据生命周期必须分开。

## 5. Windows 便携版

便携版推荐为 ZIP 目录包：

```text
Workbench-Portable/
├─ Workbench.exe
├─ Runtime/
├─ Resources/
├─ Data/
└─ portable.json
```

### 5.1 数据策略

- 可写便携介质：允许将房间数据存入 `Data/`。
- 只读介质：首次启动要求选择可写数据目录。
- 用户可切换“真正便携”与“程序便携、数据留在本机”模式。
- 便携目录移动后不得依赖原绝对路径。

### 5.2 凭据策略

便携版不得以明文保存 API Key。提供：

1. 不保存，每次使用输入。
2. 使用主密码加密的便携保险库。
3. 用户主动切换到本机系统凭据存储，此时程序便携但凭据不随目录移动。

不建议默认生成单个自解压便携 EXE；它会增加启动解压、临时目录、杀毒误报和崩溃残留问题，可作为补充发行物。

## 6. UOS/Linux 便携分发

### 6.1 AppImage

优点是单文件、通常无需安装。缺点是目标系统可能没有可用 FUSE、Chromium 沙箱条件不同，且 Electron 仍依赖部分基础 Linux 图形库。

### 6.2 解压目录版

`.tar.xz` 解压后执行启动器，是 AppImage 的必要兜底。若未来构建链内置并锁定 zstd，可再增加 `.tar.zst`。启动器需要：

- 检查 CPU 和最低系统版本。
- 设置工作台内部 Bun/Git/库搜索路径。
- 检查沙箱是否启用，不得在失败时静默使用 `--no-sandbox`。
- 输出可导出的诊断报告。

### 6.3 支持策略

先认证具体版本，例如“某 UOS 桌面版 x64 + 指定补丁级别”，而不是笼统声称支持所有国产 Linux。认证内容至少包括：

- 安装和启动。
- 中文输入法、字体和高 DPI。
- 文件选择、剪贴板和拖放。
- Chromium 沙箱。
- SQLite 锁和文件权限。
- 内网 TLS 证书和代理。
- AppImage 与目录版。
- 同一 `.room` 的兼容性。

## 7. 内置 Bun

- 每个平台携带固定版本和哈希。
- 工作台从自己的资源目录定位 Bun，不搜索系统 PATH。
- 只允许运行受控构建入口和参数，不提供房间任意命令执行。
- 构建配置启用离线模式，并将缓存指向工作台管理目录。
- 官方房间模板不需要解析新的外部依赖。
- Bun 更新随工作台或签名运行时更新包发布。

## 8. 内置 Git

### 8.1 Windows

默认采用 MinGit，因为它面向第三方应用内嵌，并去掉 Git GUI、MinTTY 和多数交互组件。只有确认需要 Bash、SSH 工具链或人工 Git 终端时才评估完整 PortableGit。

### 8.2 Linux

为每个认证目标构建或打包 Git 及必要动态库。不得假设 `/usr/bin/git` 存在，也不得自动通过系统包管理器安装。

### 8.3 隔离配置

- 从固定绝对路径启动内置 Git。
- 使用工作台专用配置，不读取不可控的系统 Git 配置。
- 默认关闭 hooks、自动子模块和危险传输协议。
- 通过结构化 Git 工具开放常用操作，不接受模型提供的任意参数数组。
- clone/fetch/push 等联网操作受工作台网络权限控制。
- 每次发行记录 Git 及其 OpenSSL、curl、OpenSSH 等组件版本和许可证。

## 9. 离线 AI 与网络

工作台必须支持三种模式：

1. **完全离线**：不配置 AI，已完成房间正常运行。
2. **隔离内网**：通过 OpenAI-compatible 或其他适配器连接内网推理服务。
3. **受控公网**：仅 AI Gateway 按 Provider 配置访问外部 API。

网络代理、私有 CA、域名白名单和超时策略属于工作台设置，房间不能绕过 AI Gateway 自行访问同一密钥或端点。

## 10. 离线资源与更新

建议定义签名更新容器 `.zupdate`，可通过 U 盘或内网文件服务器分发：

```text
update-manifest.json
payload/
integrity.json
signature.json
```

更新类型包括：

- 工作台完整更新。
- Pi Provider/模型元数据更新。
- Room SDK 与官方模块更新。
- Bun、Git 等运行时安全更新。
- 组织证书和策略更新。

更新必须支持版本检查、磁盘空间检查、签名验证、原版本保留和失败回滚。不得通过“缺什么再联网下载”完成修复。

## 11. 构建与供应链

- 所有第三方组件固定精确版本和 SHA-256。
- 构建产物生成 SBOM、许可证目录和来源 URL。
- 尽可能进行可重复构建；至少保证同一输入可追溯到相同源码和锁文件。
- 工作台安装包、运行时组件、房间包和更新包使用不同用途的签名密钥。
- 私钥不得进入构建仓库或普通 CI 日志。
- 对 Git、Electron/Chromium、Bun、SQLite 和 Pi 建立安全公告跟踪及离线更新流程。

## 12. 发布验收清单

- [ ] 在干净且无公网的目标系统首次运行。
- [ ] 系统未安装 Git、Node、Bun 时能够创建和构建房间。
- [ ] 普通用户无需 UAC/root 权限。
- [ ] 安装、升级、卸载和便携移动均不丢失房间数据。
- [ ] 内置运行时只从工作台目录加载。
- [ ] Windows 安装版和便携版通过杀毒及签名检查。
- [ ] AppImage 与目录版至少一种可在每个认证 Linux 环境运行。
- [ ] 篡改安装包、更新包和房间包会被检测。
- [ ] 第三方许可证与 SBOM 随发行物提供。
- [ ] 诊断包不包含 API Key 和授权头。
