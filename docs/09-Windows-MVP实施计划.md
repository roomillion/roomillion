# 千万间 Roomillion Windows MVP 实施计划

> 实施状态：已于 `2026-08-28` 完成本计划的 Windows x64 MVP 闭环。实际运行方法和验收结果见《10-MVP运行与验收指南》；未完成事项仍按本文的 MVP 边界处理。

## 1. 本轮目标

以当前 Windows x64 开发系统为唯一认证目标，交付一个可运行、可测试、可继续演进的 MVP。它需要证明以下闭环，而不是一次完成全部产品化能力：

1. 工作台可以显示、切换和运行多个隔离房间。
2. `.room` 可以导入，程序与数据分开保存。
3. 房间通过受控 Room SDK 使用私有 SQLite、键值存储和用户授权文件。
4. 用户可以配置一个 OpenAI-compatible API，并由 Pi AI 适配层完成模型调用。
5. 用户可以用自然语言生成一个受限格式的基础房间。
6. 系统不依赖全局 npm 包；构建产物可在当前 Windows 系统直接启动。

## 2. 本轮明确不做

- UOS/Linux 构建与验证。
- 正式代码签名、发布者证书和组织信任库。
- OAuth 订阅登录。
- 任意 npm 依赖、任意 Shell、任意后端服务。
- 完整 Pi Coding Agent UI 和自主多轮编程循环。
- 可用于不可信互联网房间市场的强安全承诺。
- 正式自动更新、`.zupdate` 和加密数据快照。

这些能力保留在总体路线图中，但不阻塞当前 Windows MVP。

## 3. 技术实现

| 模块 | 本轮选择 |
|---|---|
| 桌面外壳 | Electron + 原生 HTML/CSS/JavaScript |
| 房间隔离 | 每个活动房间使用独立 WebContentsView；关闭 Node 集成、开启上下文隔离和沙箱 |
| 宿主接口 | 独立房间 preload 暴露窄 Room SDK，主进程按 sender 映射房间 ID |
| 房间包 | ZIP 容器 `.room`，Manifest + app + integrity |
| 数据库 | `sql.js`，每房间持久化一个 SQLite 文件，避免本轮原生模块编译 |
| AI | `@earendil-works/pi-ai` 适配器；首个 UI 支持 OpenAI-compatible 配置 |
| 构建 | 当前用 Node/npm 执行仓库脚本；MVP 房间产物为静态 Web 文件，Bun 后端房间留到后续版本 |
| Git | 当前运行闭环不调用 Git；受控 Git 服务和正式 MinGit 打包进入下一发布任务 |
| 测试 | Node 内置测试运行器，核心服务不依赖 Electron UI 即可测试 |

## 4. 交付结构

```text
src/
  main/                 # Electron 主进程与服务
  preload/              # 工作台和房间的窄桥接
  renderer/             # 工作台界面
scripts/                # 示例房间打包和开发工具
test/                   # 房间包、数据库、路径和 Manifest 测试
examples/               # 示例房间源码
docs/                   # 产品和实施文档
```

## 5. 实施顺序

### M1：工程与外壳

- 建立依赖、脚本和 Electron 主窗口。
- 建立工作台 preload 和基础界面。
- 实现房间注册表、标签和 WebContentsView 生命周期。

退出条件：应用可以启动，内置示例房间可以在独立视图中打开和切换。

### M2：房间包和能力代理

- 实现 Manifest 校验、安全 ZIP 导入和完整性校验。
- 实现 `room://` 自定义协议。
- 实现每房间 SQLite、storage、文件选择和导出。
- 加入恶意路径、越权 sender 和数据库隔离测试。

退出条件：导入 `.room` 后可保存数据，重启后数据仍存在，不同房间不能互读。

### M3：AI 和最小生成闭环

- 实现 Provider Profile、内存密钥和连接测试。
- 接入 Pi AI；若上游 API 与当前版本不匹配，通过单一适配器修复。
- 使用严格 JSON 输出契约生成一个无外部依赖的房间。
- 生成前展示权限，生成后安装并打开。

退出条件：配置可用 API 后，可以从一句需求生成一个基础表单/台账房间。

### M4：验证和交接

- 运行单元和集成测试。
- 构建 Windows unpacked 应用和可分发包候选。
- 编写运行、导入、AI 配置和开发说明。
- 记录未完成风险和下一阶段任务。

退出条件：在当前 Windows 系统按说明可重复启动和完成演示。

## 6. MVP 验收脚本

1. 启动工作台，无需手工安装 Git/Bun/SQLite npm 全局包。
2. 点击“安装示例房间”，房间在标签页打开。
3. 在示例房间新增两条记录，关闭并重新打开后记录仍存在。
4. 导出示例房间为 `.room`，删除程序后重新导入；根据用户选择保留或新建数据。
5. 选择文本文件并在房间中读取，导出生成结果。
6. 配置 OpenAI-compatible 地址、密钥和模型，连接测试成功。
7. 输入“创建一个会议事项台账”，生成并打开新房间。
8. 断网后，已有房间除 AI 功能外继续正常运行。

## 7. 风险与降级策略

| 风险 | 本轮策略 |
|---|---|
| Pi 包 API 变化 | 所有调用集中在一个动态导入适配器；保留清晰错误，不扩散到 UI |
| Electron WebContentsView API 差异 | 锁定安装版本，并由单个 RoomViewManager 封装 |
| ZIP 安全实现不足 | 限制包大小、条目大小和路径；当前只导入本机/可信来源，后续增加签名 |
| sql.js 并发和大库性能 | MVP 限制房间数据规模和串行写入；产品化时评估原生 SQLite 服务 |
| AI 无法稳定输出代码 | 使用固定单页模板和严格 JSON 契约；失败时保留原始响应供诊断 |
| 便携 Git 尚未打入 | 先封装 Git 服务和固定路径发现；Windows 发行阶段替换为资源目录 MinGit |

## 8. 完成定义

- 示例房间可导入、运行、持久化和导出。

- AI 功能未配置时清晰降级，不影响本地房间。
- README 包含开发、运行和演示步骤。
