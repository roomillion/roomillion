> 实施日期：`2026-08-30`
>
> 状态：第一批、C 档办公、3D 游戏及 P0/P1/P2 扩展目录均已实现，已接入 AI Harness，并通过断网 Electron 冒烟。

2026-09-05 更新：当前目录在 22 个办公与通用模块、5 个 3D 游戏模块基础上，再加入 12 个 P0/P1/P2 扩展模块，共 39 个。办公清单和 ExcelJS 分工见《20-办公文档模块与ExcelJS决策》，3D 游戏及网络边界见《23-离线3D游戏房间第一版》，新增模块的体积、全局 API 和约束见《34-P0-P1-P2扩展模块实施记录》。39 模块离线 Electron 冒烟为 `PASS`、网络尝试 `0`。

## 1. 先看数字

“程序带了多少包”必须分层回答，不能把工作台内部依赖与房间可用能力混为一谈。

| 口径 | 当前数量 | 含义 |
|---|---:|---|
| 官方房间模块 | 39 | 房间清单可以声明的稳定能力 ID |
| AI 直接可选模块 | 37 | 另有中文字体与 PDF fontkit 两个内部依赖由工作台自动补齐 |
| 官方模块包/字体/自有工具来源 | 39 | 固定版本资源，全部随安装包离线提供 |
| 工作台直接生产 npm 依赖 | 6 | Pi AI、编码、SQLite 和房间 ZIP 读写；模块源码包主要位于构建期依赖 |
| 应用运行依赖树 | 99 个包名+版本组件 | 最终桌面应用的 Node 运行依赖 |
| 官方房间资源来源树 | 317 个包名+版本组件 | 只用于生成浏览器资源与 SBOM，不把完整源码树重复放入安装包 |
| 桌面运行时 | Electron 44.0.0 | 单独记录并随平台发行物提供 |
| 版本工具链 | Windows MinGit / Linux 便携 Git | 按平台打包，不向房间开放命令行 |

因此，对房间开发者和 AI 来说，正确答案是“默认有 39 个官方模块，其中 37 个直接可选”，不是“可以随便引用 SBOM 里的任意组件”。

## 3. AI 怎样自动选择

新的普通 AI 生成器输出完整 room-spec@1，而不是字段清单或 npm 包名：

```json
{
  "specVersion": "room-spec@1",
  "kind": "composed",
  "name": "经营分析中心",
  "data": [{
    "id": "monthly",
    "label": "月度经营数据",
    "fields": [
      { "key": "month", "label": "月份", "type": "date", "required": true },
      { "key": "revenue", "label": "收入", "type": "number", "required": true }
    ]
  }],
  "actions": [],
  "pages": [{
    "id": "dashboard",
    "title": "经营仪表盘",
    "layout": "grid",
    "columns": 2,
    "components": [
      { "id": "summary", "type": "stats", "source": "monthly", "metrics": [{ "label": "收入合计", "aggregate": "sum", "field": "revenue" }] },
      { "id": "trend", "type": "chart", "source": "monthly", "groupBy": "month", "aggregate": "sum", "valueField": "revenue" }
    ]
  }]
}
```

选型有两道控制：

1. 模型只选择受控页面、组件、动作和表达式，不输出包名或 hostModules；明确的 3D 游戏需求继续进入独立受控游戏路由。
2. 工作台根据最终字段和实际组件确定性映射官方模块。例如 date 字段映射 Day.js，chart 映射 Chart.js，搜索映射 Fuse.js，XLSX 导出映射 SheetJS。未知字段、组件、动作、表达式和规格版本直接拒绝。
3. 自由 room-app@1 的 Agent 检查能力时，会同时拿到完整目录和按当前需求生成的 recommendedModules；Agent 可自由设计交互，但最终能力仍必须通过本地白名单与强制依赖校验。

`document.markdown@1` 会自动补齐 `security.sanitize@1`。AI 修改现有房间时也会重新选型，更新后的 `manifest.json`、HTML 引用和 room-spec 保持一致。

## 4. 运行与隔离方式

- 模块资源位于工作台只读的 `resources/room-modules/`，不放入每个 `.room`，所以多个房间共用一份磁盘资源。
- 房间通过 `room://<房间-id>/_modules/<能力-id>/<资源>` 加载；运行时不访问 npm、CDN 或外网。
- 协议处理器同时检查“能力是否存在”和“房间是否在清单中声明”。即使猜到资源地址，未声明的房间也无法加载。
- 资源构建会检查 npm 包精确版本、许可证声明、许可证文件和 SHA-256；任一变化都会让构建失败。
- `.room` 只记录稳定能力 ID，因此底层包升级可以由工作台统一完成，不需要把依赖复制进每个房间。

## 5. 当前组合房间会实际使用什么

| 模块 | 已落地行为 |
|---|---|
| 日期 | date 字段统一格式化为 `YYYY-MM-DD` |
| 精确小数 | stats 和 calculator 触发金额、费率和测算能力 |
| CSV | export 组件导出 CSV，并开启公式注入转义 |
| 搜索 | table/cards/board 的 search 加载本地 Fuse.js，不发送数据 |
| 图表 | chart 组件按定义生成柱状、折线或环形图 |
| Markdown + 安全 HTML | text 组件渲染 Markdown，DOMPurify 清理后才写入页面 |
| Excel | export 组件使用工作台共享 SheetJS 生成 XLSX |

这意味着模块不是“写进清单但没用到”的装饰项。断网冒烟会加载全部 39 个模块，除搜索、合计、图表和 Markdown 清理外，还实际生成 XLSX、中文 PDF、DOCX、PPTX、ZIP 和二维码，启动 WebGL 画布与 Rapier 物理，并实际执行 12 个新增模块的主要 API，核对 `networkAttempts=0`。

## 6. 如何维护和扩充

常用命令：

```powershell
npm run build:room-modules
npm run build:compliance
npm test
npm run smoke -- --offline-audit
```

新增官方模块必须同时完成：

1. 证明需求足够常用，浏览器原生 API 不能简单可靠地替代。
2. 选择维护活跃、无安装脚本/原生二进制/运行时下载器的纯 Web 包。
3. 固定精确版本，确认 SPDX 许可证、上游许可证文件和安全公告。
4. 在 `room-module-catalog.cjs` 登记稳定能力 ID，不把 npm 包名当公共合同。
5. 在生成模板或 Room SDK 中实现实际用途，并编写模块级和断网 Electron 测试。
6. 重新生成 `resources/compliance/sbom.cdx.json` 与第三方声明。

## 7. 办公增强已经落地

XLSX、PDF、Word、PPT、图片、ZIP、二维码和中文字体保留为 22 个办公与通用模块；Three.js、Rapier、输入、音效和程序化素材组成 5 个游戏模块；Tabulator、SortableJS、Mermaid、ECharts、Quill、Leaflet、mathjs、simple-statistics、Cropper.js、Konva、D3.js 和 Cytoscape.js 组成 12 个扩展模块。办公实现见《20-办公文档模块与ExcelJS决策》，3D 实现见《23-离线3D游戏房间第一版》，扩展模块见《34-P0-P1-P2扩展模块实施记录》。

目录目标不是越多越好，而是让 80% 的常见内网小工具由少量、稳定、可审计的能力完成。每增加一个模块，安装包体积、漏洞响应和长期兼容责任都会增加。

## 8. 与房间额外依赖的关系

官方模块只在 `hostModules` 中引用，不复制进 `.room`。如果更自由的房间开发确实使用目录外包，打包器会把其实际浏览器资源和许可证放入 `embedded/`，并加入完整性校验；详细合同见《19-v1房间依赖打包策略》。当前结构化 AI 生成器只使用官方模块，不会主动引入额外包。
