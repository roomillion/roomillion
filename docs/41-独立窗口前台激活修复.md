# 独立窗口前台激活修复

版本：0.3.0-alpha.31；日期：2026-09-12。

房间弹出后，主工作台会选择备用标签；备用房间的原生 WebContentsView 获得焦点，可能将主窗口带回前台。AI 工作区的原页面关闭对话框也可能触发焦点恢复。

修复后，前端先完成备用页面切换、对话框收起和标签更新，再调用仅用于激活已存在窗口的受控 IPC。该操作不会创建已关闭的窗口。普通房间和 AI 工作区统一执行恢复最小化、显示、提升窗口层级、激活窗口及内容的流程，不设置永久置顶。

验证：

- 166 项自动测试通过，包含两个窗口管理器的最小化恢复与原窗口复用回归。
- Electron 实际界面冒烟通过：调用前端 `detachRoom` 完整流程并切换备用标签，确认独立窗口仍 `isFocused()`；AI 工作区也验证最终前台焦点。
- 同一房间 WebContents 和运行数据保持，合并、关闭行为回归通过。
- 源码测试报告：`release/alpha.31-focus-source-smoke.json`。

平台验证范围为当前 Windows x64；Linux Wayland 的窗口激活仍受桌面环境策略约束。
