# Pi 0.84.3 实际发行物许可证审查

审查日期：2026-09-10。目标：核实 Pi 实际如何发布许可证材料，为千万间 Roomillion选择适度、可执行的发布流程提供对照；不是对 Pi 或工作台作法律合规认证。

## 结论

Pi 的发布声明处理确实比较简洁：官方源码归档包含根目录 MIT 许可；本轮检查的 Windows x64 ZIP 和 4 个 npm 发布包未发现独立命名的 LICENSE、NOTICE 或第三方许可汇总文件，但包元数据声明 MIT，部分 JavaScript 内保留了第三方许可注释。

这支持我们简化审查流程，不支持把所有声明都删掉。没有独立文件不等于没有嵌入许可文本，也不足以判定 Pi 违规；本轮没有完整分析可执行文件中的全部许可文本、全部传递依赖或各组件义务。

## 分工与范围

按用户要求，安排 3 个较省成本的 `gpt-5.6-luna` 子智能体分别检查：固定版本发布脚本、实际 npm 包、实际 Windows ZIP。主智能体独立复核包内文件清单、关键许可注释、源码 LICENSE 和产物完整性。

- 对照版本为工作台使用的 Pi `0.84.3`，不是宣称当前最新版。
- 检查完整下载的 Windows x64 发布 ZIP、4 个 npm tgz、官方源码 tar.gz，以及 `v0.84.3` 标签的发布脚本。
- 未安装或运行下载的软件；没有调用用户配置的 AI API。
- 未下载其他 5 个平台的二进制实包；未执行 npm 安装，因此 4 个 npm 包不代表完整安装后的传递依赖树。
- 原始下载文件及 npm 解包内容保存在忽略提交的 `release/pi-distribution-review/`，本次不提交发行二进制。

### 确认存在的嵌入声明

`pi-coding-agent` npm 包内：

- `dist/utils/ansi.js` 开头说明部分代码来自 ansi-regex / strip-ansi，保留 Sindre Sorhus 署名和完整 MIT 许可。
- `dist/core/export-html/vendor/marked.min.js` 保留版本、版权及 MIT 标记。
- `dist/core/export-html/vendor/highlight.min.js` 保留版本、版权及 BSD-3-Clause 标记。

这些是实际发现的例子，并不证明整个 bundle 或 shrinkwrap 依赖集合的许可材料全部齐备。

### Windows ZIP 的实际分发范围

核对到 `pi.exe`（108,612,096 字节）、控制台原生模块、clipboard 原生模块、`photon_rs_bg.wasm`（1,881,634 字节）和示例中的 `doom.wasm`（380,169 字节）。clipboard 的 package.json 声明 MIT。

没有发现单独的 `git.exe`、`rg.exe`、`fd.exe`、`node.exe` 或 `bun.exe`。Pi 使用 Bun 编译独立可执行文件；这不表示没有包含运行时或第三方代码，也不表示本轮已经完整审计这些二进制内部。

## 发布流程对照

审查基于固定标签，不使用不断变化的主分支代替发布版本：

- [Windows 及其他平台打包脚本](https://github.com/earendil-works/pi/blob/v0.84.3/scripts/build-binaries.sh)：运行依赖安装、准备原生组件、使用 `bun build --compile`，复制 package.json、文档、资源和示例后生成归档。未发现复制根 LICENSE/NOTICE 或生成集中第三方许可清单的步骤。
- [源码归档脚本](https://github.com/earendil-works/pi/blob/v0.84.3/scripts/create-source-archive.sh)：使用 git archive 并补入模型数据快照，排除 node_modules 和构建好的二进制目录。源码包不是完整第三方依赖源码集合。
- [npm 包配置](https://github.com/earendil-works/pi/blob/v0.84.3/packages/coding-agent/package.json)：许可证字段 MIT，命令入口 `dist/bundle/cli.js`，Node 要求 `>=22.19.0`。
- [包管理代码](https://github.com/earendil-works/pi/blob/v0.84.3/packages/coding-agent/src/core/package-manager.ts)：Git 包的安装和更新通过 PATH 调用系统 Git；构建脚本和本轮 Windows 实包中均未发现内置 Git。不是说所有 Pi 启动操作都需要 Git。

因此，Pi 不内置 Git，而工作台内置 MinGit，这是不能直接照搬的关键差别。工作台还分发 Electron、办公处理、字体及 3D 等组件，许可范围也不同。

## 对工作台的务实建议

1. 保留现有 Apache-2.0 LICENSE、NOTICE、第三方许可目录与清单；这些已经收集好的材料不必为了模仿 Pi 再删除。
2. 将一般核查收敛为：实际分发哪些组件、版本是什么、许可原文及署名在哪里、是否有适用的额外要求。不把每个包精确追溯到 Git commit 作为统一完成门槛。
3. 原包已经带齐声明的，自动收集并随包保留；缺少独立文件的，检查源码注释和可信上游材料，不仅凭文件名判定成败，也不自行编造版权行。
4. MinGit 单独核对对应源码提供方式和随带组件，不能用 Pi 没带 Git 的发布方式替代这项工作。
5. 发布前抽查最终安装包／便携包中的声明，而不只看源码仓库是否存在文件。

本轮仅新增审查报告，没有修改原待核对清单的完成状态、删除依赖、重打工作台发行包或对外发布。之前列出的 10 项不因这份对照报告自动变成已解决；后续可以按上述更务实的证据标准重新分级处理。
