# 工作台联网控制与房间网络接口

> 实施日期：2026-09-05
> 状态：第一版已实现

## 1. 用户能得到什么

千万间 Roomillion现在把“连接 AI”和“房间访问业务网络”分开管理：

- AI 能力中心、AI 创建房间和房间的 `room.ai` 可以连接用户已配置的云端或内网模型 API。
- 主界面新增“联网控制”。其中的总开关只决定房间能否访问普通业务 HTTP/HTTPS 服务，不会关闭 AI API。
- 房间即使申请联网，也只有在主工作台允许、Manifest 已声明、用户已授权这三个条件同时成立时才能请求。
- 没有网络或总开关关闭时，离线房间照常运行，联网功能应显示不可用并给出可理解的提示。

`0.3.0-alpha.25` 另加入 `room.browser` 通用网页浏览能力。它与本章的精确源业务请求共用主工作台联网总开关，但使用单独的高风险 `browser.navigate` / `browser.download` 权限和隔离网页视图；详细规范见《37-room-browser-v1规范与浏览器房间》。

全局房间联网默认关闭，并保存在本机工作台配置中。导出 `.room` 时不会把本机的总开关和授权记录分享给别人。

## 2. 三重授权模型

```text
Manifest 精确声明目标源
          +
用户授予该房间逐源权限
          +
主工作台允许已授权房间联网
          ↓
Capability Broker 代发受控 HTTP/HTTPS 请求
```

这三层解决不同问题：

- Manifest 让房间的网络需求可审计、可分享、可在安装前展示。
- 用户授权防止外部导入房间安装后自动联网。
- 主工作台总开关让内网、涉密或临时离线场景可以一键关闭全部房间业务网络。

AI Gateway 不经过这个开关，因为“只能访问 Token API、不能访问普通互联网”是千万间 Roomillion必须支持的基础部署方式。

## 3. 房间怎样声明

`.room` Manifest：

```json
{
  "permissions": {
    "database": "private",
    "files": [],
    "ai": false,
    "network": [
      "https://api.example.com",
      "http://intranet:8080"
    ]
  }
}
```

`room-app@1` 源规格：

```json
{
  "capabilities": {
    "database": false,
    "files": [],
    "ai": false,
    "network": ["https://api.example.com"]
  }
}
```

每一项必须是精确的 HTTP/HTTPS 源，只能包含协议、主机和端口。不得写路径、查询参数、用户名或密码；声明数量不设人为产品上限。`http://intranet:8080` 这样的内网服务可以声明；是否实际可达仍由目标机器网络决定。

## 4. 房间怎样调用

房间先检查状态，再通过 Room SDK 请求：

```js
const status = await window.room.network.getStatus();
if (!status.available) {
  showMessage("请在主工作台允许房间联网，并确认本房间已获授权");
  return;
}

const response = await window.room.network.request({
  url: "https://api.example.com/v1/items",
  method: "POST",
  headers: { "content-type": "application/json" },
  body: { query: "示例" },
  timeoutMs: 15000
});

if (!response.ok) {
  throw new Error(`服务返回 ${response.status}`);
}
const data = JSON.parse(response.text);
```

总开关或房间授权变化时，可订阅状态：

```js
const unsubscribe = window.room.network.onStatusChanged((status) => {
  setNetworkBadge(status.available ? "在线" : "离线");
});
```

响应使用文本承载，房间根据业务协议自行解析 JSON。接口不会向房间暴露 Cookie、系统代理凭据、API Key 或主进程网络对象。

大响应、SSE 或二进制内容改用流式接口：

```js
const response = await window.room.network.open({ url, timeoutMs: 600000 });
try {
  while (true) {
    const chunk = await window.room.network.read(response.token, { maxBytes: 256 * 1024 });
    consume(chunk.data);
    if (chunk.done) break;
  }
} finally {
  await window.room.network.close(response.token).catch(() => {});
}
```

`room.files.beginExport/writeExport/finishExport/abortExport` 采用同样的令牌式分块写入，用于大 CSV、模型结果和二进制导出。

## 5. 当前安全边界

- 仅支持 HTTP/HTTPS；WebSocket 第一版不开放。
- 直接 `fetch`、XHR、WebSocket、EventSource 和 Beacon 仍被静态检查与 CSP 阻断。
- 请求和响应不设人为产品体积上限；大响应应流式读取。超时和最大跳转次数按任务设置，默认分别为 120 秒和 20 次。
- 每次跳转都重新校验目标源，不能借允许域跳转到未授权域。
- 禁止 Cookie、Host、Origin、代理认证等危险请求头，响应中的 Set-Cookie 不返回房间。
- 不允许用网络能力下载或执行脚本、模块、字体、原生程序，也不能代替 npm/Bun 安装。
- 外部导入房间的网络权限默认关闭；工作台内由用户明确生成并确认安装的房间仍受全局总开关约束。

这不是 Docker 式任意网络环境，而是面向非程序员的窄能力接口。HTTP/HTTPS 流式读取已经开放；后续若增加 WebSocket、组织白名单或代理配置，应作为新的显式能力单独设计和审计。

需要访问任意网页时，不应把大量域名填进 `permissions.network`。应改用 `permissions.browser` 和 `window.room.browser`；网页不会进入房间 JavaScript 上下文，也不能把通用浏览器当成读取网页内容的隐式数据接口。

## 6. AI Harness 怎样使用

房间构建技能和 Agent 系统提示已经包含联网接口规则。AI 应按以下顺序决策：

1. 普通离线需求保持 `network: []`。
2. 只有用户明确要求连接某个业务服务，且能确定精确源时才申请网络权限。
3. 生成 `getStatus()`、错误状态和超时处理。
4. 只调用 `window.room.network.request()`，不生成直接网络 API。
5. 大响应使用 `open/read/close`，大导出使用 `beginExport/writeExport/finishExport`。
6. 不猜测域名，不用网络补依赖，不把业务 API Key 硬编码进房间。

若业务服务还需要认证，第一版可由用户在房间自己的设置中输入普通业务令牌并保存在房间私有存储；组织级密钥代理和共享凭据库尚未实现，不应把密钥写进 `.room`。

## 7. 验收要点

- 总开关关闭时，已授权房间请求也必须失败。
- 总开关开启但目标源未声明或未授权时必须失败。
- 三层都满足时，请求可以成功，房间能收到状态变化事件。
- 未授权跳转和危险头必须失败；大响应用流式接口完成且不会一次性堆入渲染进程。
- 切换房间联网时，AI 能力中心和 `room.ai` 的模型连接策略不变。
- 默认关闭联网的离线审计仍应为零普通互联网请求。
