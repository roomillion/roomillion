# 现有项目迁移为房间：第一版实施记录

日期：2026-09-10。状态：源码已实现并验证，已生成 Windows x64 `0.3.0-alpha.27` 便携 ZIP；没有调用真实模型评估第三方项目的迁移质量。

## 用户怎么使用

1. 打开“AI 创建房间”，新建对话，选择编程模型。
2. 点击输入框上方的“导入项目”。阅读提示，选择自己有权使用、已清除密钥和个人数据的本地源码副本。
3. 展开项目摘要，分页查看完整文件索引和跳过统计。导入本身只进行本地读取；点击发送后，AI 才会按需分页读取源码并发送给该对话选择的模型服务。
4. AI 检查入口、配置与业务逻辑，给出迁移评估，并询问需要保留的功能、使用场景和是否接受改动。
5. 查看实施方案，点击“同意适配方案，创建新房间”或“同意重构方案，创建新房间”。不接受时可以继续提要求或停止，无需同意。
6. AI 通过现有自由房间通道写文件、检查、测试和安装。新房间仍可正常导出为 `.room`，不会修改源项目。

每个源项目使用一个独立对话。已关联房间、已有草稿或已导入项目的对话不能换入另一份源码，避免覆盖原房间或混用项目。工作台在自己的数据目录建立磁盘型只读快照；原文件后续变化不会自动同步，删除对话会同时删除该受控快照。已安装房间中的来源及许可记录不会因此删除。

## 三种结果

| 结果 | 含义 | 后续 |
| --- | --- | --- |
| 可适配（待验证） | 核心业务逻辑可保留，通过更换入口、存储、AI、联网及内置模块引用形成房间 | 展示改动、功能范围与验收方法，用户确认后生成 |
| 需要重构 | 技术栈或运行方式差异明显，需要重写界面或业务实现 | 明确保留、改写、删减和不支持部分；用户接受重构方案后生成 |
| 当前难以实现 | 当前运行边界下无法满足用户要求 | 阻止进入实施方案；解释依据，用户缩小范围后重新评估，或停止 |

“适配”不是给任意可执行程序套一层 ZIP；AI 编程仍使用 `room-app@1` 的受控 HTML/CSS/JavaScript。评估是模型判断，静态检查和隔离启动也不能代替完整业务验收。

## Harness 流程与硬性门槛

本地授权 → 源码快照 → `inspect_source_project` → `read_source_project_file` → `assess_project_migration` → 澄清需求 → `propose_room_plan` → 用户点击确认 → 分文件生成 → `test_custom_room` → `install_custom_room`。

- 源码读取工具只能接受快照清单中的相对路径，不接受任意磁盘路径。
- 未读取任何源文件不能提交评估；评估必须填写依据、保留功能、改动、依赖、风险及验收。
- 没有当前项目评估不能提迁移方案；`unsupported` 评估不能直接进入实施。
- 评估为重构时不能提交“适配”方案。迁移方式及源快照 ID 绑定到待确认方案；重新评估会使旧方案失效。
- 未经用户点击确认不能生成、测试或安装；不能通过模板工具绕过迁移评估。
- 生成仍受原有房间校验、权限和运行时边界约束，不增设 Shell 或后端执行通道。

## 读取、隐私与限制

- 支持本地 UTF-8 文本源码文件夹；不支持直接输入 GitHub URL、自动 clone、ZIP 解包或执行项目安装脚本。
- 不再限制总源码 2 MiB、180 个文件、目录深度或扫描条目数。完整索引默认每页 250 项，文本正文默认每次读取 64 KiB，可用游标和偏移继续读取。
- 排除依赖目录、版本库、构建产物、常见数据/密钥目录、疑似秘密文件、符号链接、目录联接和硬链接。普通隐藏源码文件可以进入索引；二进制或当前不支持解码的文件保留名称、大小与哈希等元数据，但不能作为文本发给模型。
- 排除常见敏感文件名及疑似硬编码密钥内容。过滤不保证识别全部秘密、个人数据或业务敏感信息；导入前的确认框明确告知源码将发往所选模型服务。
- 页面未读完不等于索引不完整；Agent 必须依据 `nextCursor` 继续翻页，并按任务读取入口、配置和相关模块，而不是一次把整个大型仓库塞给模型。
- 图片、音视频、字体、WASM、数据库等二进制资源会出现在索引元数据中，但正文不进入文本快照。需要保留这些素材的迁移仍必须明确说明缺口，不能宣称已原样打包。

## 依赖及许可证

解析各 `package.json`，将依赖名称映射到本机内置模块及版本。名称匹配只是可替换线索，不保证 API 或版本兼容；AI 仍需核对调用。

本版迁移工具不会安装或携带额外 npm 包。非内置依赖需要改用内置库、重写，或者判断当前不支持。工作台已有的底层外部依赖打包能力与这条 AI 迁移通道的能力不是同一回事。

迁移生成的房间附带 `project-migration.json`，记录来源名称、快照 ID、文件哈希、评估、迁移方式及快照中收集到的 LICENSE/NOTICE/COPYING 等文本。不会把整个原项目源码复制进房间；源码内的版权注释仍要求 AI 保留。后续从其他对话编辑该自由房间时，也保留原有迁移记录。该机制不保证自动满足所有第三方许可要求，扫描未收集到的声明需要另行补充。

## 验证结果

- 相关测试 25 项通过：快照过滤、链接阻断、分页与导入后文件变动隔离、依赖映射、限额提示、迁移评估与确认门槛、实际房间打包安装、原项目不变、许可记录随包保留及后续修改不丢失。
- 全量 `npm test`：156 项通过，0 失败。测试命令改为只发现 `test/*.test.cjs`，防止把 release 中下载的外部示例当作本项目测试执行。
- Electron 工作台冒烟测试通过：新增入口、评估显示、重复导入保护、文本转义，以及原有工作台检查。初次隔离启动遇到 GPU 子进程错误，改在正常本地环境运行并取得 PASS 报告。
- 本地冒烟证据：`release/project-migration-smoke.json`，不随源码提交。
- 未执行真实模型的第三方项目迁移评测；测试中的模型和运行验证部分使用替身，不能据此声称真实迁移“一次成功”。
