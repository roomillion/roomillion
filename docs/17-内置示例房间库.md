# 千万间 Roomillion内置示例房间库

## 1. 目标

内置示例用于让第一次接触千万间 Roomillion 的用户在不配置 AI、不安装依赖、不连接外网的情况下，立即体验“安装房间—录入数据—关闭重开—继续使用—按授权导出”的完整闭环。示例同时也是 Room SDK、权限最小化和跨平台房间合同的回归样本。

## 2. 当前示例

| 房间 | 主要用途 | 数据库 | 文件 | AI | 浏览器 |
|---|---|---:|---:|---:|---:|
| 物资台账 | 库存登记、文本读取、CSV 导出、库存分析 | 私有 | 读取、导出 | 文本分析 | 无 |
| 会议行动项 | 负责人、截止日期、优先级、完成状态和推进简报 | 私有 | 导出 CSV | 文本简报 | 无 |
| 离线 3D 晶体挑战 | Three.js 场景、Rapier 物理、收集与计时挑战 | 无 | 无 | 无 | 无 |
| AI 辩论场 | 多模型正反方辩论、人类参与、独立裁判和历史记录 | 私有 | 导出 Markdown | 主工作台多模型 | 无 |
| AI模型能力测试 | 三类三档聊天/视觉评测、Token 统计和同档排行榜 | 私有 | 读取自定义题目 | 主工作台图文模型 | 无 |
| 千万间浏览器 | 多标签网页浏览、搜索、收藏、历史、下载和网站权限确认 | 私有 | 用户确认后下载 | 无 | 导航、下载 |
| 文档浏览与转换 | 浏览 Markdown、Word、Excel、PPTX、PDF；Markdown、Word、PDF 互转 | 私有 | 读取、导出 | 无 | 无 |
| 音频分析室 | 音乐乐器与风格分析；会议录音转写 Markdown 并导出 | 私有 | 读取音频、导出 Markdown | 音频模型 | 无 |

八个房间都不使用 `window.room.network` 直连业务 API。除浏览器外均保持普通互联网离线：需要 AI 的房间只能通过工作台 AI Gateway 调用已经配置的模型；未配置 AI 时，其他本地功能照常工作。“千万间浏览器”是明确例外，它申请高风险的 `browser.navigate` 与 `browser.download`，只有用户授予房间权限且打开主工作台联网总开关后，宿主隔离网页视图才能访问普通互联网；网页本身无法取得 Room SDK、数据库或 AI Key。

“音频分析室”申请 `ai.general` 与 `ai.audio`，从工作台模型目录中筛选声明了音频输入能力的模型；音频经 AI Gateway 以 OpenAI 兼容 `input_audio` 块发送，Key 与服务地址不进入房间。“AI 辩论场”分别保存正方、反方和裁判的模型配置 ID；“AI模型能力测试”申请 `ai.general` 与 `ai.vision`，只保存脱敏模型信息、分数、设置、Token 和结果明细。API Key 与服务地址始终由主工作台 `AiService` 托管。“离线 3D 晶体挑战”只声明五个内置游戏模块，不申请数据库、文件或 AI 运行权限。浏览器的收藏夹与历史写入房间数据；Cookie、登录态、站点存储和缓存保存在按房间 ID 隔离的宿主会话中，不会随 `.room` 导出。

“文档浏览与转换”复用八个已登记许可的官方浏览器模块与受控文件接口，不引入新依赖，不申请网络或 AI 权限。Word 指 DOCX，演示文稿指 PPTX；旧式 `.doc` / `.ppt` 需先在其他程序中另存为新格式。PDF 转文本依赖文字层，扫描 PDF 需要先做 OCR；复杂的浮动图形、批注和分栏版式不能保证无损转换。房间可以浏览 XLS 和 XLSX，但电子表格当前不参与三格式互转。

## 3. 用户怎样使用

1. 在工作台左侧点击“示例房间”，或在欢迎页点击“体验示例”。
2. 查看每个房间的用途和能力标签，点击“安装并打开”。
3. 需要保存业务数据的房间第一次打开时自动创建独立数据库。
4. 同一个示例可以重新安装程序，但不会用程序包覆盖已有业务数据库。
5. 需要分享时，在工作台顶部点击“导出”；`.room` 默认只包含程序，不包含业务数据。

## 4. 开发与验证

示例源码位于 `examples/<example-id>/`，每个目录都包含 `manifest.json`、`app/index.html`、`app/styles.css` 和 `app/app.js`。重新生成全部房间包：

```powershell
npm run build:example
```

输出位于 `resources/examples/*.room`。Windows 与 Linux 打包配置只收录八个公开示例的明确文件名，目录中其他 `.room` 文件不会自动进入发行物。

验证命令：

```powershell
npm test
npm run smoke
npm run smoke -- --offline-audit
```

自动测试会检查目录 ID 唯一性、清单合法性、无直接网络 API、八个房间均可打包并通过 Windows x64 / Linux x64 房间合同。文档房间的隔离 Electron 测试使用虚构的五类文件，实际打开预览并执行六条转换路径，再检查导出文件的结构与内容。其他 Electron 冒烟覆盖数据库、WebGL 画布、Rapier 物理、AI 辩论的多模型路由、模型评测房间的三类三档界面，以及浏览器的受控标签、网页视图与窗口重挂。

## 5. 新增示例的规则

1. 公开仓库当前只包含上表八个示例。未公开示例及其素材、数据、房间包不得放入仓库。新增示例须先确认允许公开，再在 `examples/` 下建立独立目录，并同步更新 `src/main/example-catalog.cjs`、`package.json` 的打包文件名清单和公开示例回归测试。
2. 默认只使用 Room SDK 已提供的数据库、键值存储、文件和 AI 能力，不引用 CDN、远程字体或外部 npm 包。
3. 只声明确实使用的权限，不为展示方便申请额外能力。
4. SQL 必须参数化；用户内容通过 `textContent` 等安全 DOM API 渲染。
5. 示例必须提供空状态、输入约束、窄屏布局和明确的操作反馈。
6. 提交前运行完整测试与 Electron 冒烟，不只检查 `.room` 是否生成。
