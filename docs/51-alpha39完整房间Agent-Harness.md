# alpha.39 完整房间 Agent Harness

## 目标

AI 创建房间不是一次性代码生成器，而是一个能持续理解任务、读取证据、拆分工作、实施、测试、恢复和交付的编程 Agent。第一版优先让非程序员顺畅完成任务：低风险细节由 Agent 采用推荐默认，只有会改变核心功能、数据处理或 Token 费用的选择才要求用户确认。

## 一次任务的闭环

1. Agent 读取用户授权的当前房间程序或导入项目快照。
2. 对真正影响结果的事项做简短澄清；用户输入“继续”“按推荐”即可接受默认答案。
3. Agent 给出用途、操作方式、数据、权限、实施步骤和验收标准，用户确认后实施。
4. 主 Agent 可按任务复杂度把架构分析、代码审查、测试审查委派给子 Agent；不设人为数量上限，实际并发和用量由所选模型、任务配置与设备能力决定。
5. 主 Agent 根据证据写入代码，完成静态检查、契约测试、隔离启动/重载；需要真实 AI 调用时按用户选择测试。
6. 中断时保留方案和草稿，用户可继续；长对话会压缩为结构化摘要，不删除界面中的完整聊天记录。

Agent 运行中仍可发送文字或图片补充。消息会显示为已排队，并在当前工具步骤结束后通过 Pi steering 机制进入同一次运行；无需先停止，也不必等整轮结束。

## 常用指令

在输入框键入 `/` 可看到命令菜单，支持方向键和 Tab/Enter 选择。

| 指令 | 用途 |
| --- | --- |
| `/help` | 查看全部指令 |
| `/status` | 查看任务阶段、方案、草稿、运行与子 Agent 状态 |
| `/context` | 查看上下文估算和最近一次压缩 |
| `/compact` | 立即用当前模型生成语义摘要，会消耗少量 Token |
| `/runtime [output= request= run= tokens= requests= errors=]` | 查看或按当前任务调整单次输出、请求/任务超时及可选预算；`/runtime reset` 恢复模型感知默认值 |
| `/models` | 列出工作台已配置模型 |
| `/model <名称或 ID>` | 为本对话切换编程模型 |
| `/tools` | 查看可用 Harness 能力和必要边界 |
| `/retry` | 继续已确认但中断的实施方案 |

## 子 Agent

子 Agent 与主 Agent 使用同一个当前模型。第一版支持架构分析、代码审查和测试审查，不再设置每轮三个的产品上限。它们可以读取工作台能力目录、用户已授权的完整分页项目索引和当前房间程序，并把带证据的报告交回主 Agent。为避免多个执行者同时覆盖同一草稿，写文件、测试和安装仍由主 Agent 串行完成。

这不是伪并行聊天：委派会形成独立 Pi Agent 工具循环，有独立任务、上下文、状态和最终报告；报告会随会话持久保存。后续可在草稿事务和文件所有权机制成熟后，让不同子 Agent 在隔离分支上直接实现模块。

## 上下文压缩

Harness 同时提供两层压缩：

- 每轮请求前对已完成的工具参数、模型思考签名和重复目录结果做确定性瘦身。
- 接近模型上下文上限时，使用当前模型生成“目标、约束、已确认决定、进度与证据、问题与风险、下一步”结构化摘要，只保留最近完整对话继续运行。

摘要随会话保存，切换窗口或重启工作台后仍可延续。完整用户可见聊天不会因压缩删除。语义压缩失败时退回本地安全压缩，不让任务因压缩服务失败而卡死。

## 本次真实故障修复

部分 OpenAI 兼容网关在中间工具调用回复中不返回 `usage`。Pi 会在下一次模型请求前估算上下文；旧逻辑直接读取不存在的 `usage.totalTokens`，因此表现为用户输入“继续”后 0 秒报错。alpha.39 在事件返回和旧会话恢复时统一补齐标准用量对象，同时在统计界面继续把原本未返回的用量标为未知，既保证循环不中断，也不伪造账单数据。

## 当前边界

- 子 Agent 先覆盖只读分析与审查，不直接并发写同一草稿。
- 自动语义压缩会产生一次额外模型调用；`/compact` 会明确说明 Token 消耗。
- 完整对话仍保留在本地会话文件中，压缩优化的是发给模型的上下文，不是历史记录清理。
