# Pi Agent 房间开发工作区实施与使用指南

> 实施日期：2026-09-01
> 状态：持续会话第一版已实现；自由房间通道的最新设计与验收见《26-room-app@1 自由房间 Harness 实施记录》

## 1. 本次改造解决什么问题

旧的“AI 创建房间”虽然通过 Pi AI 接入模型，但本质仍是一次补全请求：用户填写一个表单，模型返回一份 JSON，工作台立即生成房间。它没有持续会话、工具执行过程、任务状态，也不能像 Codex 一样在同一上下文中继续修改。

本次改造把这个入口升级为真正的房间开发 Agent：

- 使用官方 `@earendil-works/pi-agent-core` 运行有状态 Agent 工具循环；版本与 `@earendil-works/pi-ai` 固定为同一个 `0.84.3`。
- 点击“AI 创建房间”会进入全尺寸聊天工作区，而不是一次性表单。
- AI 创建工作区和普通房间一样进入顶部标签栏；可以点击 `↗` 或拖出标签单独使用，关闭独立窗口后回到主工作台。
- 支持流式回复、运行状态、停止、补充消息排队、工具执行时间线和历史会话恢复。
- 每个开发对话都有独立的“编程模型”选择器；新对话继承当时的主工作台默认模型，之后可以独立切换并随会话持久化。
- Agent 默认加载“智变房间构建技能”，并获得工作台当前组件 DSL、3D 定义、内置模块和已关联房间上下文。
- Agent 必须调用受控构建工具。自由房间代码只能作为 `room-app@1` 草稿进入静态检查、契约测试和沙箱安装，不能直接执行模型原始回复。
- 创建成功后显示房间成果卡，可直接打开；继续对话会原位升级同一个房间并保留稳定数据源的数据。

## 2. 用户怎样使用

### 2.1 第一次创建

1. 打开“AI 能力中心”，点击“添加提供商”，输入一次 API Key，并勾选要启用的一个或多个模型。MiMo Token Plan 可以同时启用 `mimo-v2.5` 和 `mimo-v2.5-pro`。
2. 点击左侧或主页的“AI 创建房间”，工作区会作为顶部标签打开；需要更多空间时可用标签 `↗` 或右上角窗口按钮移到独立窗口。
3. 在顶部“编程模型”中选择本次任务使用的模型。这个选择只属于当前对话，不会改变其他开发对话或房间的选择。
4. 用正常语言说明目标、数据、页面和主要操作。例如：“做一个项目问题跟踪中心，要有概览统计、状态图表、问题录入、搜索表格和 Excel 导出。”
5. 发送后观察执行时间线。Agent 可能先检查内置能力，再校验、选择模块、打包、安装并建立 MinGit 检查点。
6. 成果卡出现后点击“打开房间”。

需求已经具体时，Agent 会直接构建；只有影响数据结构、产品方向或安全边界的重大歧义才应追问。

### 2.2 连续修改

房间生成后不要新开表单，直接在当前对话继续说，例如：

- “增加一个风险说明字段，保留原来的数据。”
- “概览页再加一个按优先级分组的环形图。”
- “把管理页的表格改成按状态分栏的看板，保留搜索和删除。”

Agent 再次调用构建工具时会：

1. 读取当前房间的完整受控定义；
2. 创建“Agent 修改前”MinGit 检查点；
3. 保持同一个房间 ID，递增补丁版本；
4. 保留未要求删除的数据源 ID，使已有业务记录继续可用；
5. 完成后创建“Agent 修改完成”检查点。

工作台顶部的“修改当前房间”按钮现在也会进入这种 Agent 对话，并自动关联当前本机生成房间。

### 2.3 会话与停止

- 左侧会保留本机历史房间开发对话；关闭窗口或重启工作台后可以恢复。
- 每个会话保存所选模型配置 ID。重新打开后仍使用原模型；如果该模型已从 AI 能力中心删除，界面会要求重新选择，而不是静默改用另一个模型。
- Agent 运行期间模型选择器锁定；停止或完成后才能切换，避免一轮工具调用中途更换模型。
- Agent 运行时仍可发送补充要求，消息会排队，在当前工具步骤完成后继续处理。
- 点击“停止”会清除等待消息并取消当前模型或工具运行。已经完成安装的房间不会因为停止按钮被删除。
- API Key 不写入 Agent 会话、房间、MinGit 或普通 Provider 配置；只有用户主动选择“系统安全存储记住密钥”时才由 Electron 安全存储加密保存。

## 3. 架构

```text
聊天工作区
  │ 发送/停止/恢复会话
  ▼
RoomAgentService
  │ 会话 profileId + 系统上下文 + 默认 SKILL.md + 当前房间定义
  ▼
Pi Agent Core（状态、流式事件、工具循环、队列、取消）
  │
  ├─ Pi AI Provider → MiMo / 其他已配置 AI API
  │
  ├─ inspect_room_capabilities
  ├─ build_room
  └─ build_3d_room
       │
       ▼
本地严格校验 → 内置模块推导 → .room 编译安装 → MinGit 检查点
```

职责边界：

| 层 | 负责 | 不负责 |
|---|---|---|
| Pi AI | Provider、协议、模型和流式 API 适配 | 房间格式与安装 |
| Pi Agent Core | 有状态消息、工具调用循环、事件、排队、停止 | 执行任意系统命令 |
| RoomAgentService | 产品提示词、技能、会话持久化、工具授权与界面事件 | 网络下载依赖 |
| 房间编译器 | 校验 DSL 或自由房间代码、推导模块、生成和安装房间 | 无检查地信任模型输出 |
| MinGit | 创建与恢复程序检查点 | 存储 API Key 或业务数据库内容 |

## 4. 默认技能和工具

默认技能位于 `src/main/skills/room-builder/SKILL.md`，它明确规定工作流、产品边界、room-spec@1 规则、连续修改的数据兼容要求和用户回复方式。技能随安装包一起进入应用，不依赖外网下载。

当前给 Agent 六项工具：

| 工具 | 用途 | 安全边界 |
|---|---|---|
| `inspect_room_capabilities` | 查看受控组件、39 个内置模块和当前需求的推荐模块 | 只读，不扫描用户文件 |
| `build_room` | 构建普通办公、数据、看板、计算器房间 | 只接受 room-spec@1 JSON；无任意代码、无网络 |
| `build_3d_room` | 构建收集、迷宫、跑酷三类离线 3D 房间 | 使用固定 Three.js/Rapier 等内置模块和数值边界 |
| `draft_custom_room` | 草拟固定模板无法表达的新游戏或定制应用 | 只接受 room-app@1；检查格式、代码、模块和权限 |
| `test_custom_room` | 对自由草稿做安全、交互、游戏和 3D 契约测试 | 失败必须重写草稿，不能安装 |
| `install_custom_room` | 最终复检、离线打包、安装或升级自由房间 | 只接受本会话已测试草稿；网络固定为空 |

模型提交的是 JSON 字符串。工具会再次解析、严格校验引用关系和数量边界，并根据用户原始要求做质量门禁。校验失败时错误返回给 Agent，由 Agent 修正规格后重试；不合格内容不会安装。

## 5. 会话数据与隐私

会话按文件保存在工作台用户数据目录的 `mvp-data/agent-sessions/`。每个文件只包含：

- 会话 ID、标题、状态和时间；
- 用户与 Agent 的对话消息；
- 工具名称、进度、成功或失败状态及脱敏成果摘要；
- Pi Agent 为后续对话保留的模型消息；
- 关联房间 ID、模型配置 ID、Provider ID、显示名称和模型名称。

不保存 API Key。工具参数中的完整 room-spec 不进入前端公开步骤卡；它只存在于受控 Agent 上下文和已生成房间定义中。诊断事件仍只记录房间 ID、版本、类型、模块数量和质量结果，不记录聊天内容。

## 6. 离线与依赖规则

- Agent 调用阶段需要能访问用户配置的 Token API；不需要访问 npm、GitHub、CDN 或普通互联网。
- 房间运行阶段默认不访问任何网络。
- AI 普通房间使用工作台现有模块，`.room` 的 `embeddedDependencies` 为空；不会重复打包内置包。
- `@earendil-works/pi-agent-core` 是工作台自身依赖，不属于房间依赖；它及传递依赖已进入 SBOM 和第三方声明。
- 会话和技能全部保存在本地，可在无普通互联网的内网环境使用。

## 7. 验收证据

### 7.1 自动测试

- 全部测试：截至 2026-09-04 的 alpha.3 主线为 101/101。
- Agent 专项测试验证：新建、消息流、工具进度、room-spec 构建、同房间升级到 v1.0.1、MinGit 检查点和重启恢复。
- Electron 离线冒烟验证 Agent 对话框、历史会话、默认技能、三条建议、时间线和停止按钮；后续验收还实际运行并关闭了 Three.js 自由房间，同时全部 39 个模块继续通过；普通互联网出站尝试为 0。

### 7.2 真实 MiMo v2.5

使用 MiMo Token Plan 的普通 `mimo-v2.5` 做了真实 Agent 验收，结果位于 `release/mimo-agent-smoke.json`：

- 总耗时约 41 秒；
- Agent 先检查工作台能力，再调用 `build_room`；
- 一次成功生成“培训课程与报名管理中心”；
- 2 个页面；组件包括 hero、stats、chart、form、table、export；
- 自动复用 6 个内置模块；
- 随房间额外依赖为 0；网络权限为空；
- 质量门禁通过；创建了初始 MinGit 检查点。

测试密钥未写入报告或仓库。实际使用中，如果密钥曾粘贴到聊天、工单或其他外部位置，仍建议在提供商后台轮换。

## 8. 当前限制与下一步

- 当前不是操作系统级通用代码 Agent；它可构建 room-spec@1、模板化 3D 和 room-app@1 沙箱自由房间，但不能生成原生程序、执行 Shell 或访问任意系统资源。
- 当前已支持 PNG、JPEG、WebP、GIF 图片的选择、粘贴和拖入；普通 `mimo-v2.5` 支持图片输入，`mimo-v2.5-pro` 保持文本输入。PDF/TXT 等通用文件附件、分支会话、上下文压缩和工具权限逐次确认界面尚未实现。
- 运行中补充消息采用完成当前工具步骤后继续的队列语义，不会中断已经开始的原子打包操作。
- 会话记录当前保存在本机 JSON 文件；正式多用户版需要配额、归档、删除确认和组织审计策略。
- Agent 可以通过校验失败修正，但模型质量仍会影响交互轮数；需要继续积累真实需求做评测集。

建议下一阶段按优先级实施：会话归档界面、生成前规格摘要与权限预览、工具调用确认策略、上下文压缩、PDF/TXT 等附件读取技能、针对典型办公/3D 需求的自动评测集。会话删除和图片附件已经完成。
