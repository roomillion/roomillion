# alpha.40 灵活多文件房间与可扩展运行时

## 本轮目标

初始阶段优先保证房间灵活、好用，不再用面向演示规模的固定容量阻挡真实项目。本轮完成四条主线：完整项目索引、多文件自由房间、模型感知 Agent 运行参数，以及网络/导出/数据库/向量的可扩展通道。

## 已实现

- 项目导入建立工作台数据目录内的只读磁盘快照。依赖、构建、数据和疑似秘密目录仍排除；其余文件形成完整索引，不再受 2 MiB、180 文件或 12 层目录限制。索引默认 250 项一页，文本默认 64 KiB 一页。
- `room-app@1` 保留三个兼容入口，同时支持任意数量的安全相对路径文本文件。入口模块可静态导入其他 JS/MJS 模块，额外 CSS 自动加载，安装和再次 AI 修改时会完整恢复文件清单。
- Agent 单次输出默认读取模型目录声明的 `maxTokens`，上下文按模型 `contextWindow` 自动压缩。通用模型默认单请求 3 分钟、推理模型 10 分钟；任务默认 30 分钟。用户可用 `/runtime` 独立调整输出、请求超时、任务超时和可选预算，默认不设置 Token、请求次数或工具错误次数配额。
- `room.network` 增加 `open/read/close`；`room.files` 增加 `beginExport/writeExport/finishExport/abortExport`。小数据继续使用原一次性 API，大数据使用令牌分块，避免单次 IPC 聚合。
- 房间数据库改为宿主磁盘 SQLite。向量集合、条数、维度、批量、文本、元数据、`topK` 不再设置演示型产品上限，精确余弦搜索按批从磁盘读取。
- 大文本和二进制文件不再限制源文件总大小，单次分块保留 64 MiB 技术边界；房间、数据库和数据归档不再使用旧 50–384 MiB 产品配额。

## 仍然保留的边界

保留的是格式正确性、权限和主机稳定性边界，不是 P0/P1 业务配额：相对路径不能越界；房间不能直接取得 Node/Electron、Shell、密钥或任意磁盘路径；网络仍要求 Manifest、用户授权和总开关；模型声明的真实输出上限仍生效；ZIP 导入保留反压缩炸弹边界；流式单块大小必须能被当前进程安全分配。

## 房间开发建议

复杂房间默认拆成 `modules/`、`views/`、`services/` 和 `styles/`。大响应、大导出、大文件和知识库一律走分块接口并展示进度与取消；不要因为接口不再限量就一次把所有数据装入渲染进程。Agent 应先读取完整分页索引，再按需求选择相关源码，而不是把整个项目一次发送给模型。
