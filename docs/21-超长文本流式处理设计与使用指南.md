# 千万间 Roomillion超长文本流式处理设计与使用指南

## 1. 实施状态

- 实施日期：`2026-08-31`
- 状态：第一阶段已进入源码开发版
- 目标文件：TXT、日志、Markdown、CSV/TSV、JSONL/NDJSON 等可顺序解码的文本
- 核心原则：文件留在用户选择的位置；不进入 `.room`、房间数据库或房间完整内存

原有 `room.files.pickText()` 适合 10 MB 以内的小文件，它会一次读取并通过 IPC 返回完整字符串。1 GB 文件不能沿用这条链路，否则主进程、IPC 序列化和房间渲染进程都可能出现数倍内存占用和长时间卡顿。本次新增独立的 `room.largeText` 能力，旧接口保持兼容。

## 2. 已实现架构

```text
用户选择本地文件
    ↓（绝对路径只进入主进程）
LargeTextService ── 文件句柄 + 流式解码器
    ↓（临时令牌、元数据、≤1 MB 文本块）
受权限控制的 IPC
    ↓
房间 room.largeText API
```

后台搜索使用单独的只读文件流，不改变分块预览的游标。搜索只保留关键词边界和摘要所需的小段字符，因此即使文件只有一行且超过 1 GB，也不会把整行累积到内存。

## 3. 权限与安全边界

房间必须在 `manifest.json` 中声明：

```json
{
  "permissions": {
    "files": ["largeText"],
    "network": []
  }
}
```

`files.largeText` 与普通 `files.pick` 分开授权，遵循以下约束：

- 每个文件都必须由用户通过系统窗口主动选择。
- 房间得不到盘符、目录或绝对路径，只获得随机临时令牌和安全元数据。
- 令牌绑定房间 ID，其他房间不能使用；关闭房间、删除房间或退出工作台时释放句柄。
- 同一房间最多保留 8 个打开令牌，超过时关闭最早的令牌。
- 每次 `readNext` 最多读取 1 MB 原始字节，默认 512 KB。
- 当前单文件安全上限为 20 GB；这是产品保护值，不代表所有机器都能以相同速度处理 20 GB。
- 工作台在读取前核对文件身份、大小和修改时间；文件发生变化后要求用户重新选择。
- 搜索词限制为 1～200 个字符，结果最多 1000 条；房间可以申请更低的上限。
- 房间不能借此执行 Shell、访问目录、写回源文件或绕过网络策略。

## 4. 编码策略

当前内置 UTF-8、GB18030/GBK、UTF-16 LE、UTF-16 BE 和 Big5。自动识别顺序为：

1. 识别 UTF-8/UTF-16 BOM。
2. 用零字节分布识别无 BOM 的 UTF-16。
3. 对样本执行严格 UTF-8 校验。
4. 无法通过时回退到 GB18030。

自动识别不是统计学万能检测。遇到乱码时，示例房间允许用户手动切换编码；切换后解码器和读取位置会回到文件开头。`iconv-lite 0.7.3` 由工作台统一携带，采用 MIT 许可证并进入 SBOM，房间包不会重复携带它。

## 5. Room SDK 使用

```js
const file = await room.largeText.open({ encoding: "auto" });
if (!file) return; // 用户取消

const chunk = await room.largeText.readNext(file.token, {
  maxBytes: 512 * 1024
});
console.log(chunk.text, chunk.progress, chunk.eof);

const { taskId } = await room.largeText.startSearch(
  file.token,
  "错误",
  { caseSensitive: false, maxResults: 500 }
);

const unsubscribe = room.largeText.onTaskEvent((event) => {
  if (event.taskId !== taskId) return;
  if (event.type === "progress") console.log(event.progress, event.matches);
  if (event.type === "complete") console.log(event.results, event.truncated);
});

// 不再使用时释放；关闭房间时宿主也会兜底释放。
await room.largeText.close(file.token);
unsubscribe();
```

搜索结果包含 `line`、`column`、`characterOffset` 和截断后的 `snippet`。行列和字符偏移基于解码后的 JavaScript 字符串，适合界面定位，不应作为原始字节偏移使用。

## 6. 当前边界与下一阶段

第一阶段解决“安全打开、分块查看、查找关键词”，尚未把所有大数据处理都包装成结构化 API：

- CSV：当前可当文本预览和搜索；下一阶段增加逐行 CSV 解析、列选择、过滤和分批聚合。
- JSON：优先支持 JSONL/NDJSON；单个 1 GB JSON 对象需要专用 token 流式解析器，不能调用 `JSON.parse`。
- 改写与导出：下一阶段增加宿主侧流式转换管道和临时文件原子导出，房间只提交结构化规则。
- 索引：频繁重复搜索可增加可撤销的本地索引，但索引必须与源文件指纹绑定并受容量策略管理。
- AI：不能把 1 GB 原文直接发给模型；应先在本地筛选、分段、脱敏，再由用户确认发送摘要或选中片段。

## 7. 验证要求

相关自动测试覆盖 UTF-8/GB18030 跨块解码、编码切换、超长单行、跨流边界搜索、大小写搜索、结果上限、取消、令牌跨房间隔离和源文件变化检测。发布前还应在普通办公电脑上使用真实 1 GB、5 GB 日志做耗时与内存基线，并在 Windows x64 和目标 UOS x64 上分别执行 Electron 离线冒烟。
