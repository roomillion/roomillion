# 离线 3D 游戏房间第一版

> 实施日期：2026-09-01
> 状态：Windows 开发版与单文件便携版已实现并通过真实运行验收

## 1. 结论与网络边界

第一版已经支持在“不能访问普通互联网，但能访问已配置 Token API”的环境中用 AI 创建 3D 游戏房间。

- 创建或修改时：只有工作台的 AI Gateway 访问用户选择的 Token API。
- 游戏运行时：房间声明 `network: []`，不访问 Token API、npm、CDN、素材站或普通互联网。
- 分享时：`.room` 只包含受控游戏定义和约 10 KB 的固定模板代码，不重复携带工作台已有的 Three.js、Rapier 等公共资源。
- 接收方：只需安装同一兼容版本的千万间 Roomillion，导入 `.room` 即可离线运行，不需要 Node、Bun、Python、npm 或管理员权限。

这不是让模型生成任意 JavaScript。模型只生成经过白名单和数值边界校验的 JSON；工作台使用固定模板构建游戏，因此更适合内网分发、跨平台运行和一次成型。

## 2. 第一版内置模块

| 能力 ID | 实现与版本 | 许可证 | 用途 |
|---|---|---|---|
| `graphics.three@1` | Three.js 0.185.1 | MIT | WebGL 场景、相机、光照、材质和动画 |
| `physics.rapier@1` | Rapier 3D Compat 0.20.0 | Apache-2.0 | 内联 WASM 刚体、重力和碰撞 |
| `game.input@1` | 智变输入工具 1.0.0 | MIT | WASD、方向键、空格和触屏按键 |
| `game.audio@1` | 智变音频工具 1.0.0 | MIT | Web Audio 程序化提示音，不需要音频文件 |
| `game.assets@1` | 智变程序化素材工具 1.0.0 | MIT | 角色、障碍、晶体和基础材质 |

所有版本、许可证原文、大小和 SHA-256 均进入模块目录、SBOM 与第三方声明。Three.js 和 Rapier 只在工作台中保留一份；多个房间共享只读资源。

开源组件仍然有著作权，准确表述是“当前选择了允许分发的宽松许可证并履行随附许可证义务”，不是“没有版权”。公开发行前仍应由组织法务复核。

## 3. AI 生成合同

用户明确同时提到“3D/三维/WebGL”和“游戏/迷宫/跑酷/收集”等词时，Harness 自动进入 3D 游戏路由。模型只能返回如下受控数据：

```json
{
  "name": "霓虹迷宫",
  "description": "穿过立体迷宫收集全部晶体",
  "genre": "maze",
  "difficulty": "normal",
  "theme": "neon",
  "instructions": "使用 WASD 移动，空格键跳跃",
  "seed": "offline-maze-one",
  "player": { "speed": 6.2, "jumpForce": 7.5 },
  "level": {
    "size": 28,
    "obstacleCount": 12,
    "collectibleCount": 8,
    "timeLimitSeconds": 120
  }
}
```

本地校验会强制：

- `genre` 只能是 `collector`、`maze`、`runner`；
- 难度和主题只能来自固定枚举；
- 速度、跳跃、场地、障碍、收集物和时限都有上下界；
- 自动绑定五个游戏模块，不接受模型输出的 URL、脚本、包名或 `hostModules`；
- 第一次结果不合格时，用质量错误自动修复一次；第二次仍不合格则不安装房间；
- AI 修改只更新同一受控定义，房间版本递增，并保留 Git 修改前检查点。

## 4. 当前可做什么

第一版固定模板提供：

- 第三人称 3D 场景、阴影、雾效、四种主题；
- Rapier 重力、刚体、静态障碍、边界墙和跳跃；
- 收集物、计时、胜负、重新开始和暂停；
- WASD、方向键、空格与触屏虚拟按键；
- 程序化收集、跳跃、成功和失败音效；
- 可复现的种子关卡；
- 收集挑战、迷宫、障碍跑酷三类参数化布局；
- WebGL 不可用或 WASM 启动失败时的可见错误提示。

内置“离线 3D 晶体挑战”可在不配置 AI 的情况下直接体验。打开“示例房间”，选择该示例并安装即可。

## 5. 怎样使用 Token API 创建

1. 打开“AI 能力中心”。
2. 选择 MiMo Token Plan 或其他 Pi 内置 Provider，只输入 Key 并选择模型。
3. 点击“AI 创建房间”。
4. 明确写出 3D 游戏类型、主题、难度、目标、数量和时限，例如：

   `创建一个 3D 迷宫游戏：玩家在霓虹迷宫里用 WASD 和空格移动跳跃，在两分钟内收集 8 枚晶体，难度适中，游戏运行时必须完全离线。`

5. 生成后直接试玩；需要调整时点击 AI 修改，用自然语言修改主题、难度、数量或玩法类型。
6. 点击导出获得 `.room`，发送给其他千万间 Roomillion用户。

推荐让内网防火墙只放行实际使用的 Token API 域名。房间进程本身仍不能直接联网；AI 响应经工作台主进程接收，模型不会获得任意本地文件权限。

## 6. 安全实现

- 房间继续运行在 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false` 的独立分区中。
- 房间协议只提供清单中已声明的模块资源，猜测其他模块地址会被拒绝。
- CSP 只增加 `wasm-unsafe-eval` 以允许 Rapier 编译 WebAssembly；普通 JavaScript `eval` 仍禁止。
- `connect-src 'self'`、`network: []`、禁止新窗口和跨房间导航保持不变。
- 3D 示例不申请数据库、文件或 AI 运行权限。
- 程序化素材避免自动下载来历不明的模型、贴图、字体或声音。

## 8. 第一版限制与下一步

当前不是通用 Unity/Unreal 替代品，也不承诺“任何 3D 游戏一次生成”。第一版暂不支持：

- AI 任意编写游戏脚本或自定义着色器；
- 导入 glTF/FBX、外部贴图、背景音乐和大体积素材包；
- 联机多人、账号、服务器权威同步；
- 复杂骨骼动画、导航网格、粒子编辑器、关卡编辑器；
- 统信 UOS 指定版本的显卡驱动实机认证。

下一阶段应优先增加受控实体/组件定义、内置 glTF 素材白名单、性能档位与显卡能力检测，再评估更自由的脚本沙箱。Linux/UOS 发行物需要基于新增 3D 资源层重新构建，并在指定系统和显卡上验证 WebGL/WASM。
