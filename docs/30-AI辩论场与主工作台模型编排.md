# AI 辩论场与主工作台模型编排

## 1. 已实现的目标

“AI 辩论场”是一个内置示例房间。它参考 ModelScope AI_Debate 的核心产品流程，保留主题设置、正反方角色、AI/人类参与、轮次控制、暂停继续、独立裁判和历史记录，同时用千万间 Roomillion Room SDK 重新实现。房间不自带模型服务，不要求用户重复填写 API Key 或服务地址。

## 2. 使用方法

1. 先在主工作台“AI 能力中心”配置至少一个可用模型。若希望角色使用不同模型，可配置两套或更多模型。
2. 打开“示例房间”，安装并进入“AI 辩论场”。
3. 输入主题，分别选择正方、反方和裁判的参与类型及模型。
4. 设置总发言次数和每次篇幅，点击“开始辩论”。
5. 人类角色轮到发言时可提交观点或跳过；运行中可暂停、继续和重置。
6. 辩论完成后，裁判给出结构化评议。记录保存在房间私有数据库中，也可导出为 Markdown。

“灵感命题”同样使用当前选择的裁判模型生成，不访问普通互联网。

## 3. AiService 调用链

```text
AI 辩论场
  ├─ listModels() ──读取──> 主工作台脱敏模型目录
  ├─ generate(prompt, { profileId: 正方 }) ──> Room IPC ──> AiService
  ├─ generate(prompt, { profileId: 反方 }) ──> Room IPC ──> AiService
  └─ generate(prompt, { profileId: 裁判 }) ──> Room IPC ──> AiService
                                                     └─ 使用主工作台托管的凭据调用 Token API
```

房间只接触配置 ID、显示名称、模型名、能力和就绪状态。API Key、自定义服务地址和认证头不会进入渲染进程、房间数据库、导出的辩论记录或 `.room` 文件。

本房间是多角色场景，因此不使用 `selectModel` 在每轮覆盖房间默认模型，而是为正方、反方和裁判分别保存 `profileId`，每次调用 `generate(prompt, { profileId })` 做单次路由。模型配置发生变化时，房间通过 `onModelsChanged` 重新读取目录。

## 4. 辩论编排

- 发言从正方开始，正反交替；“总发言次数”按单次发言计数。
- AI 辩手只收到主题、立场、篇幅约束和此前辩论记录，并被要求回应对方论点。
- 人类辩手的发言进入同一记录，后续 AI 和裁判都能看到。
- 达到轮次后，独立裁判根据论证、证据、反驳、结构和表达给出评议。
- 重置会递增运行令牌，已返回的旧异步结果不能写入新一轮辩论。
- AI 调用失败时会停止在可恢复状态，用户可检查模型配置后继续。

辩论记录属于不可信数据：提示词明确要求模型只把记录作为待分析内容，不能把记录中的文本当成系统指令执行。

## 5. 权限与离线边界

房间清单只声明：

- `database: private`：保存会话和发言历史；
- `files: ["export"]`：由用户主动导出 Markdown；
- `ai` 文本能力：经工作台 AI Gateway 调用模型；
- `network: []`：房间不能直接发起普通网络请求。

所以“不能使用普通互联网，但可以使用 Token API”的环境可以运行：房间本身无网络权限，只有主工作台 `AiService` 能连接用户已配置的模型端点。

## 6. 回归验证

自动测试检查示例清单、打包合同、AI 权限和无直连网络代码。Electron 冒烟会创建两套模拟模型配置，实际安装并启动房间，令正方和反方选择不同模型，完成两轮发言和裁判评议，并验证：

- 模型选择器来自主工作台；
- 正方、反方和裁判按指定 `profileId` 路由；
- 消息顺序为系统、正方、反方、裁判；
- 房间没有 API Key 或服务地址输入框；
- 辩论完成后历史记录写入私有数据库。

源码位于 `examples/ai-debate/`，生成的房间包位于 `resources/examples/ai-debate.room`。
